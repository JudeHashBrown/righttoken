# RightToken 用户运营管理后台使用手册设计

## 目标

为普通运营人员提供一份无需技术背景即可独立使用的工作手册。读者应能在首次阅读后完成每天的常见工作：看概览、处理任务、查用户、发邮件或回复邮件、查看用户分组和查看数据报表。

## 读者与范围

手册只面向角色为“运营人员”的成员，只介绍普通运营每天能看到并需要使用的六个模块：

1. 用户运营概览
2. 任务中心
3. 用户中心
4. 邮件中心
5. 用户分组查看
6. 数据报表

不介绍客户分配、提醒设置、成员与权限、系统设置、CSV 导出、分组规则发布等管理员专属功能。必要时仅提示“该操作由管理员处理”，不展开后台规则。

## 交付形式

- 可编辑的 Word 文档（DOCX）
- 便于直接分发和阅读的 PDF
- 中文简体
- 预计 15–20 页
- 使用紧凑型操作指南版式，适合屏幕阅读和打印

## 内容结构

### 1. 封面与使用说明

- 手册名称、适用角色、版本日期
- 一句话说明系统用途
- 手册阅读建议

### 2. 五分钟快速上手

用一张日常工作流程图说明：

`进入后台 → 查看概览 → 优先处理紧急任务 → 查看用户详情 → 联系用户并记录 → 更新任务状态 → 查看当天结果`

同时说明如何从 RightToken 主站进入用户运营管理后台，以及如何返回主站。

### 3. 每天推荐工作顺序

提供可直接照着执行的上班、工作中和下班前检查清单：

- 上班先看哪些数字
- 哪些任务优先处理
- 什么时候进入用户中心
- 什么时候使用邮件模板
- 处理完后需要留下哪些记录
- 下班前如何确认没有遗漏

### 4. 六个模块的详细说明

每个模块统一使用以下结构：

1. 这个页面是做什么的
2. 页面上的数字、分组和状态怎么看
3. 常用操作步骤
4. 推荐操作习惯
5. 常见问题与处理方法

#### 用户运营概览

- 查看待办、紧急事项、用户变化和渠道情况
- 从概览进入需要立即处理的任务
- 识别需要优先处理的信息

#### 任务中心

- 理解任务列表、负责人、优先级和处理状态
- 筛选自己的任务
- 打开任务详情
- 从任务进入关联用户或写邮件
- 开始处理、等待用户、完成和转交任务
- 添加处理记录和用户备注

#### 用户中心

- 使用搜索、分组、国家、地区和负责人筛选
- 理解 F、A、B、C、D、E、G 分组的运营含义
- 打开用户详情
- 查看注册、地区、支付、余额、调用、负责人、任务和时间线
- 添加运营备注
- 从用户详情主动写邮件
- 说明普通运营不能手工修改用户分组

#### 邮件中心

- 理解邮件统计入口和会话列表
- 查看用户来信和历史会话
- 回复用户邮件
- 主动给用户写邮件
- 选择公共模板并在发送前修改正文
- 插入图片和管理附件
- 处理无法自动关联用户的来信
- 理解草稿、待处理、失败、退订和人工归档状态

#### 用户分组查看

- 查看各组定义、筛选条件、当前人数和最近变化
- 理解互斥分组和优先顺序对运营工作的影响
- 强调运营人员只查看，不发布或修改分组规则
- 提供 A–G 分组的简明运营解释

#### 数据报表

- 查看用户、任务、邮件和运营结果
- 理解常见指标
- 按时间或范围查看变化
- 用报表检查自己的工作结果
- 说明普通运营不能导出完整 CSV

### 5. 跨模块操作

使用流程卡片说明：

- 任务 → 用户详情 → 写邮件 → 更新任务
- 用户中心 → 用户详情 → 添加备注
- 用户来信 → 回复 → 关联用户与任务
- 分组变化 → 查看原因 → 决定是否需要联系用户

### 6. 常见问题与处理

覆盖运营最常遇到的问题：

- 找不到某个用户
- 邮件没有发出去
- 用户回复没有自动关联
- 任务为什么又被重新打开
- 用户为什么进入某个分组
- 页面没有某个管理员按钮
- 数据刚发生变化但页面还没更新
- 不确定是否应该联系用户

## 写作与界面表达标准

- 使用运营语言，不暴露数据库字段、接口名、布尔值或内部规则表达式
- 每个操作以动作开头，如“点击”“选择”“填写”“确认”
- 每个流程最多 7 个步骤，复杂流程拆成多个小流程
- 重要提醒使用“注意”卡片，错误处理使用“遇到问题时”卡片
- 不写测试账号、密码、密钥、真实用户邮箱或 IP
- 不展示管理员才可见的内部配置界面
- 分组只解释运营含义，不向普通运营讲规则发布和全量重算

## 视觉设计

- 采用 `compact_reference_guide` 设计预设
- RightToken 蓝紫色作为主强调色，深蓝标题，浅灰背景和浅色提示框
- 标题层级清晰，正文使用易读中文字体
- 用流程图、步骤卡、状态表和检查清单替代大段说明
- 页眉显示“RightToken 用户运营手册”，页脚显示页码和版本日期
- 表格保持少列、宽描述列和足够内边距

## 验收标准

- 普通运营不依赖管理员或开发人员即可理解六个模块用途
- 每个模块至少包含一个完整的常用操作流程
- 跨模块闭环能够从任务开始，完成联系用户、记录和更新状态
- 全文不出现数据库、接口、代码字段或后端规则措辞
- Word 文档和 PDF 的全部页面经过渲染检查，无重叠、裁切、乱码或断页问题
- 文档不包含任何真实用户敏感信息
