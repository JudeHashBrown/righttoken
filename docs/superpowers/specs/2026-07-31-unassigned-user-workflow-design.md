# 管理员待分配用户工作流设计

## 目标

管理员登录召回管理台后，应能第一时间发现尚未分配运营负责人的用户，并可通过确认地区触发自动匹配，或直接人工指定运营人员。任何情况下，如果现有分配规则找不到可负责该用户的运营人员，用户都必须继续保持“未分配”状态，不再默认转交主管理员。

## 用户体验

### 管理员首页

- `PRIMARY_ADMIN` 和 `ADMIN` 的用户运营概览增加“待分配用户”指标。
- 指标显示 `ownerId = null` 且未从主站删除的用户数量。
- 点击指标进入 `/users?ownerId=__UNASSIGNED__`。
- `OPERATOR` 不显示该指标，也不能借助查询参数扩大自己的用户范围。

### 用户中心

- 负责人表头筛选增加“未分配”选项。
- 选择“未分配”后仅展示 `ownerId = null` 的有效用户。
- 所有用户继续按最近发生时间到最早发生时间排列；待分配视图采用相同顺序。
- 未分配用户的负责人栏明确显示“未分配”，并为管理员提供“立即分配”操作。

### 分配编辑器

管理员可在一次操作中：

1. 仅指定国家和可选省份/地区；
2. 仅指定运营人员；
3. 同时指定地区和运营人员。

提交时必须填写调整原因。

- 仅指定地区：将地区标记为人工确认，然后立即运行当前已发布的自动分配规则。
- 仅指定运营人员：将负责人标记为人工分配，不改变地区。
- 同时指定地区和运营人员：先保存地区，再以人工指定的运营人员作为最终负责人；自动规则不得覆盖人工选择。
- 未填写地区和负责人时禁止提交。

国家使用两个字母的大写国家码。中国大陆省份/地区使用现有 `region` 自由文本值，保持与分配规则的“地区包含”条件兼容。

## 分配语义

### 自动匹配

自动分配继续使用现有规则优先级：

1. 省份/地区规则优先于国家规则；
2. 同一具体程度内按规则优先级匹配；
3. 主负责人不可用时使用规则的备用负责人；
4. 没有规则命中、规则未配置负责人、主备负责人都不可用，或负载上限不允许接单时，返回 `assigneeId = null`。

不再把主管理员作为全局默认负责人。主管理员只有被某条分配规则明确配置为主负责人或备用负责人时，才会被自动匹配。

### 未分配状态

- `UserProfile.ownerId = null` 是用户未分配的唯一事实来源。
- 自动分配未命中时保持：
  - `ownerId = null`
  - `ownerAssignmentMode = AUTO`
  - `ownerAssignedAt = null`
  - `ownerAssignedById = null`
  - `ownerAssignmentReason` 保存“没有可用负责人”等可展示原因。
- 未分配用户可以直接进行首次人工负责人分配，不要求先经过一次成功的自动分配。
- 若地区变更导致原自动负责人不再匹配且没有新负责人，自动负责人应被清空；人工负责人锁定时，地区变更不覆盖负责人。

### 任务处理

- 用户从未分配变为已分配时，其尚未开始或进行中的开放任务同步转交给新负责人。
- 用户从一个负责人切换到另一个负责人时，继续沿用现有开放任务转交逻辑。
- 自动重算后仍未分配时，不制造虚假的任务负责人；任务保持未分配状态。

## 服务边界

### 查询层

- `UserFilters.ownerState` 支持 `unassigned`，避免使用伪造成员 ID 表达空值筛选。
- 管理员首页快照增加 `unassignedUsers`。
- 管理员查询待分配用户时使用 `ownerId: null`；运营人员仍严格限制为自己的 `ownerId`。

### 领域服务

- 自动分配服务允许返回空负责人，并负责把此前的自动负责人清空。
- 人工负责人服务允许对 `ownerId = null` 的用户执行首次分配。
- 新增一个管理员分配编排服务，按“地区更新 → 自动匹配 → 可选人工负责人覆盖”的顺序，在同一数据库事务中完成操作和审计。
- 现有单独地区接口和负责人接口继续可用，避免破坏用户详情页。

### 接口

新增管理员接口：

`PATCH /api/users/:id/assignment`

请求字段：

```json
{
  "countryCode": "CN",
  "region": "广东",
  "ownerId": null,
  "reason": "确认注册地区并按华南规则分配"
}
```

`countryCode` 与 `ownerId` 至少提供一项。若未提供 `countryCode`，不得单独提交 `region`。

响应返回最终地区、最终负责人、分配模式、命中的规则和转交任务数。接口执行同源校验，并要求 `operators:manage` 权限。

## 审计

每次组合分配写入一条 `user.assignment_resolved` 审计记录，至少包含：

- 操作者；
- 调整前后国家和地区；
- 调整前后负责人；
- 最终负责人分配模式；
- 命中的规则；
- 调整原因；
- 转交任务数量。

现有单独地区和负责人操作继续使用原审计事件。

## 错误处理

- 非管理员返回 `403`。
- 用户不存在或已从主站删除返回 `404`。
- 国家码、地区、负责人或原因无效返回 `400`。
- 目标负责人已停用返回 `409`。
- 自动规则未命中不是错误：接口成功返回，最终负责人为空，用户继续显示在待分配列表。
- 并发操作通过用户行锁串行化，最终结果以最后一个成功事务为准。

## 测试与验收

自动化测试覆盖：

- 自动规则命中后分配对应运营；
- 中国省份规则优先于国家规则；
- 无规则或无可用运营时保持未分配；
- 自动重算可清空不再匹配的旧自动负责人；
- 未分配用户可首次人工指定负责人；
- 同时指定地区和负责人时人工负责人优先；
- 负责人筛选的“未分配”语义；
- 管理员首页待分配数量和入口；
- 运营人员看不到入口且不能查看全局未分配用户；
- 接口校验、权限和审计数据。

浏览器验收覆盖：

1. 管理员首页显示待分配数量；
2. 点击进入按时间倒序的待分配用户列表；
3. 仅指定地区且规则命中后，用户从列表消失并显示匹配运营；
4. 指定没有负责人规则的国家后，用户仍留在列表；
5. 直接指定运营后，用户从待分配列表消失；
6. 运营人员登录后看不到管理员入口。

## 非目标

- 不新增轮询、推送或站外通知；管理员通过首页指标发现待分配用户。
- 不自动创建国家或省份分配规则。
- 不改变人工负责人锁定语义。
- 不引入新的地区字典或地图选择器。
