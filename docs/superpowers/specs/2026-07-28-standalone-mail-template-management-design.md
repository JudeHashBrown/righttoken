# 独立邮件模板管理设计

## 目标

邮件中心始终显示“模板管理”入口。即使系统没有任何用户来信，管理员和运营人员也可以进入独立页面创建、编辑、启用或停用公共邮件模板。

## 交互

- 邮件中心标题右侧固定显示“模板管理”按钮。
- 点击后进入 `/mail?view=templates`，页面标题保持“邮件中心”，主内容切换为公共模板管理。
- 模板管理页显示所有未归档模板的最新版本，包括已停用模板。
- 左侧/顶部以标签切换模板，右侧/下方直接编辑模板名称、邮件主题和正文。
- 修改现有模板后点击“发布新版本”，不覆盖历史版本。
- 已停用模板仍然可见，并可重新启用。
- “返回邮件列表”一步回到 `/mail?view=replies`。
- 新建模板沿用现有内联表单，不使用弹窗。

## 权限

- 主管理员、管理员、运营人员均可创建、修改、启用和停用公共模板。
- 历史版本归档权限仍仅属于主管理员，本次不新增归档界面。

## 数据与错误处理

- 不新增数据表或迁移。
- 工作台查询改为每个模板 key 返回最新、未归档版本，不再只返回启用模板。
- 创建、发布版本和启停继续调用现有邮件模板接口。
- 保存失败时在编辑区内显示错误，保留当前编辑内容。

## 验收

- 没有选中邮件时也能看到并进入模板管理。
- 没有邮件会话时也能创建模板。
- 已停用模板在管理页可见且可重新启用。
- 回复邮件时仍只展示启用模板。
- 单元测试、集成测试、类型检查、代码规范和生产构建通过。
