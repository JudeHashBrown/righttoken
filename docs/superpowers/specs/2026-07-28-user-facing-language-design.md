# 用户运营后台前端语言设计

## 目标

将用户运营后台所有可见文字改为运营人员和管理员能直接理解的业务语言。后端枚举、错误码、数据库术语、任务队列术语和规则引擎实现细节不得直接出现在页面上。

## 语言原则

1. 页面优先说明“发生了什么、意味着什么、下一步能做什么”。
2. 不显示内部枚举、布尔值、错误码、事件代码、数据库名称、队列状态或接口实现。
3. 后端仍使用稳定的机器值；前端在统一的展示层转换后再渲染。
4. 无法识别的新状态统一显示安全文案，例如“状态正在更新”或“暂时无法显示，请稍后重试”，不得回退显示原值。
5. 运营人员必须填写的连接信息可以保留，但使用任务语言命名，例如“发件服务器地址”和“收件服务器地址”；协议缩写只作为必要的辅助说明。
6. 分组和分配页面可以展示管理员需要配置的业务条件，但不得出现“字段、枚举、布尔值、规则引擎、全量重算、队列”等实现语言。

## 统一展示层

在 `recall-admin/src/modules/presentation/` 建立集中转换函数，覆盖：

- 用户地区、支付、余额和调用状态；
- 任务状态、优先级和操作结果；
- 用户时间线事件和错误原因；
- 邮件状态、同步结果和发送错误；
- 分组发布、用户重新归类和历史方案状态；
- 系统连接状态和成员权限状态。

组件只渲染转换后的文案。内部日志和接口请求继续使用原始机器值。

## 页面改写范围

### 仪表盘

将系统实现型指标改为运营结果，例如“待处理用户”“需要跟进”“邮件连接情况”。不展示内部同步、任务生成或计算过程。

### 用户与用户详情

地区显示国家和省份的业务名称；没有省份时显示“国家已确认”。支付状态显示“未产生付费记录”“已支付”或“支付状态正在更新”。时间线使用“完成注册”“开始支付”“完成首笔支付”“调用成功”“调用失败”等业务事件，不显示事件代码或错误码。

### 任务中心

状态使用“待领取、处理中、等待用户、已完成、已暂停、已取消”。任务详情说明当前负责人、联系进度和下一步操作，不使用“用户 360”“事件事实”等内部描述。

### 邮件中心

邮件收发、会话、模板和邮箱连接均使用客服工作语言。同步失败必须显示可执行的解决办法，不显示内部错误码。主动写信、回复、模板和图片能力保持不变。

### 用户分组

页面使用“当前方案、覆盖用户、最近整理、未完成用户”等业务语言。“全量重算”改为“重新整理全部用户分组”，“规则版本”改为“分组方案记录”，“字段/判断/值”改为“筛选依据/条件/目标”。

### 分配与通知

使用“客户来源、负责地区、负责人、通知时机、通知方式”等业务语言。不得展示规则匹配、优先级算法、回退键、Webhook 等内部术语；必须配置的企微地址放在“高级连接信息”中并给出用途说明。

### 报表、成员与设置

报表聚焦运营结果。成员页使用“授予权限、撤销权限、停用访问”等语言。设置页使用“数据连接、客服邮箱、企业微信通知”分区，不直接展示数据库产品名、后台 API 或运行组件。

### 登录与授权

仅说明需要从 RightToken 主站进入、当前账号无权限或登录状态已失效，不暴露令牌、安全校验和认证实现。

## 错误处理

- 已知错误由错误码映射为用户可执行的中文提示。
- 未知错误显示统一通用提示。
- 原始错误仅进入服务端日志，不进入 React 页面、提示条或弹窗。
- 对邮箱、企微和主站连接分别给出对应的检查建议。

## 防回退检查

增加单元测试和静态文案审计：

- 验证所有展示转换函数的正常值和未知值；
- 扫描前端源码，禁止原始枚举、原始错误码和高风险后台术语出现在可见文案；
- 对确有必要的配置缩写使用显式白名单；
- 保持现有单元、集成、端到端、类型、代码规范和构建检查通过。

## 不改变的范围

- 不改变后端数据结构、接口机器值或分组业务判断；
- 不改变主管理员、管理员、运营人员的权限边界；
- 不删除管理员完成工作所需的配置项和操作；
- 不在本次改动中调整页面布局或视觉设计。
