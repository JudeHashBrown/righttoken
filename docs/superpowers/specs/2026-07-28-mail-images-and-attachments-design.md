# 邮件图片与附件闭环设计

## 目标

让运营人员在邮件模板和邮件回复中插入图片、添加图片附件，并在运营工作台中安全查看用户来信里的正文图片和附件。

首版只处理图片，不扩展 PDF、Office 文档、压缩包或视频。支持 JPEG、PNG 和 WebP，拒绝 SVG、GIF 和无法识别真实格式的文件。

## 用户体验

### 模板管理

- “邮件正文”升级为可视化编辑器，保留常用文字排版能力。
- 编辑器工具栏提供“插入正文图片”和“添加图片附件”。
- 正文图片插入当前光标位置，可设置替代文字、预览、更换或删除。
- 图片附件显示在正文下方的紧凑附件列表中，可预览和删除。
- 发布模板新版本时，正文、纯文本备用内容、图片和附件共同形成不可变版本。
- 停用模板不删除历史资产，历史已发送邮件仍能查看。

### 回复用户

- 选中模板时，同时载入文字、正文图片和图片附件。
- 运营人员可继续修改文字、删除模板图片、替换图片或新增图片。
- 发送前显示最终预览和附件数量。
- 发送失败时保留当前编辑内容，避免重新填写。

### 查看来信

- 来信正文中的 CID 内嵌图片显示在邮件正文对应位置。
- 普通图片附件显示文件名、格式、大小、预览和下载操作。
- 外部远程图片默认不加载，避免触发邮件追踪；页面提示“已阻止外部图片”。
- 无法安全解析的 HTML 回退为纯文本正文。

## 数据结构

### `MailAsset`

保存图片资产元数据，不把二进制图片写入数据库：

- `id`
- `storageKey`
- `fileName`
- `contentType`
- `byteSize`
- `sha256`
- `width`
- `height`
- `createdById`
- `createdAt`

### `MailTemplate`

在现有 `bodyText` 之外新增 `bodyHtml`。`bodyText` 是不支持 HTML 的邮箱客户端所使用的备用正文。

### `MailMessage`

在现有 `bodyText` 之外新增 `bodyHtml`。出站消息保存实际发送版本，入站消息保存经过清洗并完成 CID 替换的版本。

### 资产关联

使用独立关联表，避免把文件信息塞进 JSON：

- `MailTemplateAsset`：模板版本、资产、`INLINE`/`ATTACHMENT`、CID、排序。
- `MailMessageAsset`：消息、资产、`INLINE`/`ATTACHMENT`、CID、排序。

模板发布后关联不可修改。发送时把模板资产复制为消息关联，保证历史邮件不受模板后续版本影响。

## 存储

定义统一的 `MailAssetStorage` 接口：

- `put`
- `get`
- `delete`
- `exists`

开发环境使用本地持久化目录，默认 `recall-admin/.data/mail-assets`。生产环境使用 S3 兼容对象存储，通过以下环境变量配置：

- `MAIL_ASSET_STORAGE=s3`
- `MAIL_ASSET_S3_ENDPOINT`
- `MAIL_ASSET_S3_REGION`
- `MAIL_ASSET_S3_BUCKET`
- `MAIL_ASSET_S3_ACCESS_KEY_ID`
- `MAIL_ASSET_S3_SECRET_ACCESS_KEY`
- `MAIL_ASSET_S3_FORCE_PATH_STYLE`

对象存储桶保持私有。后台预览和下载统一经过授权接口，不提供永久公共链接。

## 上传和安全

- 单张图片不超过 5 MB。
- 单封邮件最多 10 张图片。
- 单封邮件图片总大小不超过 20 MB。
- 使用 `sharp` 读取真实图片格式和尺寸，不能只相信浏览器上传的 MIME 类型。
- 图片重新编码并移除 EXIF 等元数据。
- JPEG、PNG 和 WebP 输出保持原格式或转为安全的同类格式。
- 文件名只用于展示，存储键使用随机 ID。
- 图片下载接口验证当前成员是否有邮件权限。
- 下载响应设置正确的 `Content-Type`、`Content-Length`、`X-Content-Type-Options: nosniff` 和安全的 `Content-Disposition`。

## HTML 与 SMTP

编辑器保存受限 HTML，不允许任意脚本、样式、表单、iframe 或外部资源。

正文图片在数据库 HTML 中使用受控资产标识。发送时：

1. 为每张正文图片生成稳定 CID。
2. 把 HTML 资产标识替换为 `cid:` 地址。
3. 从私有存储读取图片。
4. 通过 Nodemailer `attachments` 发送，正文图片带 CID，普通附件不带 CID。
5. 同时发送 `html` 和 `text` 两种正文。

因此收件人不需要登录 RightToken，也不依赖公开图片链接。

## 收件解析

IMAP 同步使用 `mailparser` 读取：

- 纯文本正文
- HTML 正文
- CID 内嵌图片
- 普通图片附件

每张安全图片写入资产存储并关联到新建的 `MailMessage`。HTML 经过白名单清洗，CID 引用替换为后台授权预览地址。外部 `http`/`https` 图片移除并记录“已阻止外部图片”状态。

如果存储写入失败，本封邮件仍保存纯文本正文，并记录稳定错误码供后台重试，不让一次损坏附件阻塞整个邮箱同步。

## 接口

- `POST /api/mail/assets`：上传并返回资产元数据。
- `GET /api/mail/assets/:id`：授权预览或下载。
- 模板创建与版本接口新增 `bodyHtml` 和资产关联列表。
- 邮件发送与回复接口新增 `bodyHtml` 和资产关联列表。
- 邮件工作台查询返回安全 HTML、图片附件列表和外部图片拦截状态。

所有接口继续复用现有主管理员、管理员和运营权限。运营人员只能在自己有权处理的邮件和任务范围内发送、查看和下载资产。

## 错误处理

用户可见错误使用明确中文：

- “图片格式不支持，请上传 JPG、PNG 或 WebP”
- “单张图片不能超过 5 MB”
- “一封邮件最多添加 10 张图片”
- “图片总大小不能超过 20 MB”
- “图片上传失败，请重试”
- “该图片已失效，请重新上传”

发送前再次验证所有资产存在且当前用户有权使用。任一资产缺失时禁止发送，避免用户收到破损正文。

## 测试与验收

### 自动测试

- 上传格式、真实文件签名、大小、数量和权限校验。
- 本地与 S3 存储适配器契约测试。
- 模板版本保存正文图片和附件。
- 选中模板后回复编辑器正确载入并允许修改资产。
- SMTP 同时发送 HTML、纯文本、CID 图片和普通附件。
- IMAP 正确解析 CID 图片和普通图片附件。
- 外部图片被移除，危险 HTML 被清洗。
- 无权成员不能预览或下载图片。
- 退订、暂停联系、联系频率和任务归属等现有发送拦截仍然生效。

### 人工验收

- 在模板正文中插入图片，发布版本，再用该模板回复测试邮箱。
- 分别在 Namecheap Webmail、企业微信邮箱和常见手机邮箱查看正文图片和附件。
- 从测试邮箱回复一封带 CID 图片和普通图片附件的邮件，在运营工作台查看和下载。
- 关闭对象存储或模拟丢失资产，确认页面和发送流程给出清晰错误且不会发送破损邮件。

## 非目标

- 首版不支持视频、音频、压缩包、Office 文档和 PDF。
- 首版不做图片裁剪、滤镜或复杂排版设计器。
- 不自动加载用户来信中的外部远程图片。
- 不把图片二进制内容存入 PostgreSQL。
