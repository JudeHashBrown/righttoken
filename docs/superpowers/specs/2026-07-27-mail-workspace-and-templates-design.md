# 邮件工作台与公共模板设计

## 目标

将现有邮件中心从统计页升级为运营可直接处理用户来信的工作台，并提供可由主管理员、管理员和运营人员共同维护的公共邮件模板页签。

首版完成以下闭环：

1. 从统计卡片进入对应邮件列表。
2. 查看用户来信正文及同一会话的历史邮件。
3. 对用户来信直接回复，并保留邮件会话关系。
4. 无法自动关联用户的来信可以人工关联。
5. 使用公共模板快速填写回复内容，并允许修改本次邮件。
6. 所有成员均可新增、更新和停用公共模板，模板变更保留版本和审计记录。

## 页面结构

邮件中心继续使用 `/mail`，避免运营在多个页面间来回切换。

页面由四部分组成：

### 1. 可点击统计卡片

现有八张卡片全部成为筛选入口：

- 邮件回复任务
- 待处理回复
- 已退订用户
- 已启用邮箱
- 人工归档箱
- 草稿
- 发送失败
- 最近同步

点击卡片后仍停留在 `/mail`，通过查询参数切换工作区内容，例如：

- `/mail?view=replies`
- `/mail?view=pending`
- `/mail?view=unmatched`
- `/mail?view=drafts`
- `/mail?view=failed`

“已退订用户”和“已启用邮箱”分别显示受限用户列表和邮箱连接状态；“最近同步”显示每个邮箱的最后同步结果。

### 2. 会话列表

工作区左侧显示与当前筛选条件匹配的邮件会话或未归档来信，每项展示：

- 用户名称或发件邮箱
- 主题
- 最新邮件摘要
- 最新来信时间
- 未处理状态
- 当前负责人

运营人员只能看到自己负责的用户和任务；主管理员、管理员可以看到全部会话。

### 3. 会话详情

工作区中部显示：

- 用户名称、邮箱、分组、地区和负责人
- 会话内按时间排列的收件与发件记录
- 每封邮件的完整纯文本正文
- 发件人、收件人和时间
- 关联任务及处理状态

首版只展示纯文本邮件正文，不直接渲染来信 HTML，避免不可信 HTML、脚本或跟踪资源进入管理后台。

未匹配来信在同一区域显示正文，并提供“关联用户”操作。关联完成后，系统创建或并入邮件会话，并按现有规则创建邮件回复任务。

### 4. 回复编辑器与模板页签

回复编辑器位于会话详情下方，包含：

- 收件邮箱
- 发件邮箱
- 邮件主题
- 邮件正文
- 公共模板页签
- 发送按钮

公共模板以横向页签展示。点击模板后，将该模板的主题和正文复制到当前编辑器。运营可以自由修改本次内容；修改编辑器不会自动覆盖公共模板。

编辑器提供三个模板动作：

- `保存为新模板`：创建一个新的模板系列。
- `更新当前模板`：为当前模板创建下一个版本，不修改旧版本。
- `停用当前模板`：不再在默认页签中展示，但保留历史版本和已发送邮件引用。

切换模板时，如果当前正文已经被修改，页面提示用户确认放弃本次未发送修改。

## 模板权限与版本

主管理员、管理员和运营人员都可以：

- 创建公共模板
- 为公共模板发布新版本
- 停用或重新启用模板
- 在回复前修改本次内容

所有模板变更记录操作者、时间和版本号。

模板版本不可原地覆盖。更新模板时创建相同 `key`、更高 `version` 的新记录，并将新版本设为当前版本。历史已发送邮件继续保留发送时使用的 `templateKey` 和 `templateVersion`。

主管理员可以查看完整模板历史，并将错误版本归档。归档是软删除，不清除数据库记录、审计记录或已发送邮件引用。

## 数据模型

复用现有 `MailTemplate`、`MailThread` 和 `MailMessage` 模型。

`MailTemplate` 增加：

- `updatedAt`：当前版本记录更新时间。
- `archivedAt`：主管理员归档时间。
- `archivedById`：执行归档的成员。

模板版本仍使用现有 `(key, version)` 唯一约束。`active` 表示该模板系列的当前可用版本。

`MailMessage` 已保存 `bodyText`、`threadId`、`providerMessageId`、`inReplyTo` 和 `references`，继续作为会话和回复关联依据。

人工关联未匹配邮件时，补齐该邮件的 `userId`、`threadId`，将状态从 `UNMATCHED` 更新为 `RECEIVED`，并保证同一邮件不会重复创建任务。

## 回复数据流

1. 邮箱同步任务通过 IMAP 拉取新来信。
2. 系统优先使用 `In-Reply-To` 和 `References` 匹配已发送邮件。
3. 匹配成功后，来信进入对应 `MailThread`，并创建或复用邮件回复任务。
4. 运营在邮件中心打开会话，选择模板并编辑本次回复。
5. 发送前继续执行退订、暂停联系、联系频率和权限校验。
6. SMTP 发送时携带被回复邮件的 `Message-ID` 作为 `In-Reply-To`，并合并 `References`。
7. 发送成功后写入 `MailMessage`、任务活动和审计日志；发送失败则保留失败记录和稳定错误码。

## 接口边界

新增或扩展以下后台接口：

- `GET /api/mail/workspace`：按筛选条件返回统计、会话列表和当前会话详情。
- `POST /api/mail/messages/:id/assign`：将未匹配来信关联到用户。
- `POST /api/mail/reply`：在线程中发送审核后的回复。
- `GET /api/mail/templates`：读取当前可用模板及允许查看的版本。
- `POST /api/mail/templates`：创建模板系列。
- `POST /api/mail/templates/:key/versions`：发布新版本。
- `POST /api/mail/templates/:id/archive`：主管理员归档错误版本。
- `POST /api/mail/templates/:key/toggle`：停用或启用模板系列。

接口必须在服务端执行成员身份、角色、用户范围和邮件发送权限校验，不能依赖前端隐藏按钮实现安全控制。

## 错误处理

- 邮箱未连接：回复编辑器禁用，并引导到系统设置。
- 来信未关联用户：禁止直接发送，必须先完成关联。
- 用户已退订或暂停联系：服务端阻止发送。
- 模板切换存在未保存修改：要求确认后才能覆盖编辑器。
- SMTP 发送失败：保留失败邮件，允许从“发送失败”筛选重新打开。
- IMAP 同步失败：邮箱状态显示错误码和最后成功时间，不阻断其他邮箱。
- 同一来信重复同步：通过 `providerMessageId` 保证幂等。
- 两人同时更新模板：按版本号创建新版本，版本冲突时要求刷新后重试。

## 测试范围

### 单元测试

- 统计卡片生成正确筛选链接。
- 模板选择会复制主题和正文。
- 修改本次正文不会修改模板对象。
- 有未发送修改时切换模板需要确认。
- 各角色均可创建、更新和停用模板。
- 只有主管理员可以归档模板版本。
- 回复请求正确生成 `In-Reply-To` 和 `References`。

### 集成测试

- 未匹配来信可关联用户、创建会话且只创建一次任务。
- 模板更新创建新版本并保留旧版本。
- 回复成功后保存模板版本、会话和审计记录。
- 已退订、暂停联系或无权访问用户时拒绝回复。
- 发送失败邮件能被失败筛选查询到。

### 端到端测试

- 从“待处理回复”卡片进入列表，打开用户来信并查看正文。
- 选择模板页签、修改正文并发送回复。
- 新建模板后立即出现在模板页签。
- 运营人员可以维护模板，但不能归档历史版本。
- 人工归档箱来信可以关联用户并进入正常会话。

## 非目标

首版不包含：

- 富文本或 HTML 邮件编辑器
- 邮件附件上传和预览
- AI 自动生成回复
- 自动发送未经人工审核的回复
- 个人私有模板
- 删除已发送邮件或审计记录

这些功能可在纯文本会话闭环稳定后单独设计。
