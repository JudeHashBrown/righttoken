# A 组用户运营页面设计

## 目标

在现有 B 组入口下方新增独立的 A 组运营页面。A 组页面直接复制 B 组页面的布局、操作流程和数据联动方式，再按 A 组用户特征调整分组条件、页面文案、模板范围和邮件默认用途。

## 用户定义与排序

A 组用户必须同时满足：

- 用户当前分组为 `A`；
- 用户未被源系统删除；
- 用户尚未发起支付，`checkoutStartedAt` 为空。

列表按注册时间 `registeredAt` 从新到旧排序；注册时间相同则按用户 ID 倒序，保证顺序稳定。搜索支持注册序号和邮箱关键词。运营人员只能看到其权限范围内的用户。

用户一旦发起支付并由现有分组系统进入 B 组，将自动从 A 组页面消失并出现在 B 组页面。页面不自行修改用户分组，只读取现有自动分组结果。

## 导航与页面文案

- 页面路径：`/groups/a`。
- 左侧导航在 B 组下方新增“A组”。
- 顶部工作区标题：`A组 · 新注册但未发起支付`。
- 页面主标题：`新注册但未发起支付`。
- 灰色可能原因：
  - 还不清楚 RightToken 的用途；
  - 偶然在社交媒体看到，出于好奇注册；
  - 浏览价格后认为价格偏高。

## 页面布局

A 组直接复制 B 组布局，不抽取新的通用分组工作台：

- 左侧保持 176 像素窄用户列；
- 用户列显示注册序号、邮箱和系统判定国家；
- 右侧保持五个紧凑胶囊及中间箭头；
- 已完成的步骤单独高亮；
- 邮件、联系方式、优惠券和日常维护在当前页面内展开；
- 邮件与日常维护展开区填满右侧工作区；
- 维护记录只在点击“日常维护”后显示。

A 组使用独立的 `a-group` 页面、组件、类型和查询文件。B 组代码不改造成共享架构，避免本次功能扩大为重构任务。

## 五个操作步骤

### 用户身份

第一个胶囊显示注册序号和邮箱，只作为当前用户标识。

### 发邮件

- 显示已发送、已收到和已退信数量；
- 可在当前页面填写主题和正文并发送；
- A 组默认邮件用途为 `KNOWLEDGE_SHARE`（知识分享）；
- 仍可选择支付跟进、产品更新、活动通知和其他；
- 模板范围为 A 组模板和无分组模板；
- 知识分享或产品更新邮件成功发送后，自动同步为日常维护记录；
- 退信仍显示，但不计入有效维护完成状态。

### 登记联系方式

支持登记微信号、Telegram、手机号国家区号和手机号。联系方式按用户永久保存，用户进入其他分组后仍保留。

### 送优惠券

沿用 B 组规则：每位用户可获得一张 USD 1.43 优惠券，永久限送一次。只有真实发券服务成功返回后才显示成功；服务未配置或调用失败时不得伪造成功状态。

### 日常维护

- 在右侧工作区全宽显示；
- 支持运营手工填写维护日期和记录内容；
- 显示全部历史维护记录及日期；
- 知识分享和产品更新邮件自动同步到记录；
- 退信邮件的维护记录标记为无效，不点亮当前阶段的维护完成状态。

## 分组阶段与高亮勾稽

邮件完成和日常维护完成按用户最近一次进入当前 A 组的时间计算。用户离开 A 组后重新进入 A 组，旧邮件和旧维护记录继续可见，但不会点亮本次 A 组阶段的完成状态。

联系方式完成和优惠券完成是用户级永久状态，不因 A、B、C、G 等分组变化而重置。

## 权限与错误处理

- 页面读取和所有写操作继续沿用现有运营权限；
- API 校验同源请求、登录身份和用户操作权限；
- 联系方式、维护记录和优惠券失败时在当前展开区显示明确错误；
- 邮件发送沿用现有邮箱可用性、退订、暂停和联系频率保护；
- A 组页面不得展示内部判定表达式、数据库字段或后端逻辑说明。

## 测试与验收

- 查询测试覆盖 A 组条件、权限范围、注册时间排序和搜索；
- 阶段测试覆盖重新进入 A 组后的邮件与维护高亮；
- 组件测试覆盖 A 组标题、原因文案、窄用户列、五步胶囊和默认知识分享；
- 导航测试覆盖 B 组下方的 A 组入口及顶部标题；
- 浏览器验收覆盖页面加载、搜索、邮件展开、联系方式展开和日常维护全宽展开；
- 全量单元测试、类型检查、代码规范、网页生产构建、Worker 构建和端到端测试必须通过。
