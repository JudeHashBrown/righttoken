# 访问地域口径与采集链路修复设计

## 背景

用户列表已经能显示新加坡、英国等运营归因地区，但访问看板只出现未知、美国和中国香港。两处页面当前都使用“国家或地区”措辞，容易让管理员误以为它们读取同一份数据。

实际存在两套独立事实：

- 用户运营地区保存在 `UserProfile.countryCode`，可能来自邮箱域名规则、注册 IP、主站事件或人工确认。
- 访问地域保存在 `SiteVisit.countryCode`，只代表页面浏览发生时的实时访问 IP。

生产排查还发现访问采集链路存在部署缺口：主站没有配置可信代理，召回后台仍运行不含访问看板的旧镜像，数据库未执行 `SiteVisit` 迁移，GeoIP 数据文件也没有经过部署前校验。这些缺口会让真实访问被记为未知，或者让主站静默丢弃访问转发错误。

## 目标

1. 明确区分“实时访问 IP 国家”和“注册用户运营归因国家”。
2. 在同一访问看板展示两套统计，让新加坡、英国等用户归因地区有明确入口。
3. 保持访问 UV/PV 的地理数据只来源于实时访问 IP，不用邮箱推断污染流量统计。
4. 当未知访问异常时，向管理员展示可执行的 GeoIP 状态说明。
5. 让真实 IP、访问转发、数据库迁移和 GeoIP 文件成为可验证的部署前置条件。
6. 保持访问采集失败不影响主站浏览体验，同时留下可诊断日志。

## 非目标

- 不把用户邮箱后缀国家写回 `SiteVisit`。
- 不把匿名访问强行关联到用户档案。
- 不改变现有 UV 去重、PV 累计、北京时间日期边界和 180 天保留策略。
- 不在本次改动中实现登录用户与匿名访客占比。
- 不自动信任任意 `X-Forwarded-For`，也不使用 `0.0.0.0/0` 作为可信代理范围。

## 方案选择

采用“口径分离并同时展示”的方案：访问看板保留实时访问 IP 统计，并新增注册用户归因国家统计。拒绝使用用户档案国家覆盖访问国家，因为英国用户可能只是由 `.uk` 邮箱后缀推断，覆盖后会让流量地域失真。

## 数据与查询设计

### 实时访问 IP 国家

现有 `SiteVisit` 聚合保持不变：

- 查询周期受 7、30、90 天选择器控制。
- UV 按 `visitorHash` 去重。
- PV 按访问事件计数。
- 国家来自访问发生时解析的公网 IP。
- 无法识别的访问统一使用 `ZZ`。

页面标题改为“访问 IP 国家或地区”，说明文字明确指出该表不读取用户档案地区。

### 注册用户运营归因国家

新增用户国家聚合查询，数据来源为仍有效的 `UserProfile`：

- 只统计 `sourceDeletedAt IS NULL` 的用户。
- 按 `countryCode` 分组并统计当前用户数。
- 空值和非法国家码统一显示“未识别”。
- 结果按用户数降序、国家码升序排列。
- 该表展示当前用户存量，不受访问看板 7、30、90 天选择器影响。

页面标题为“注册用户运营归因国家”，列为“国家或地区、用户数、用户占比”。说明文字明确该结果可能来自邮箱域名、注册 IP、主站事件或人工确认。

查询代码保持职责分离：访问聚合继续位于 `modules/visits`，用户归因聚合新增为独立查询模块，不把两套来源拼成一个国家字段。

## GeoIP 状态设计

新增只读的 GeoIP 运行状态检查，判断当前进程是否拥有可用的数据来源：

1. 配置且可读取 GeoLite2 City MMDB：状态为“城市库可用”，支持国家和中国大陆省份。
2. 仅配置且可读取 RIR 数据：状态为“国家库可用”，支持国家但不保证省份。
3. 配置 HTTP GeoIP 服务：状态为“远程服务已配置”。
4. 所有来源均不可用：状态为“GeoIP 未配置或文件不可读”。

当周期内存在 `ZZ` 时，页面结合运行状态显示提示：

- 数据源不可用：明确要求部署 GeoIP 数据文件或 HTTP 服务。
- 数据源可用：说明剩余未知通常来自内网、保留地址或查询未命中。

状态检查不得输出 Token、文件内容或访问 IP。

## 真实 IP 与转发错误

主站继续通过 Gin 的可信代理机制读取客户端 IP。部署必须显式配置实际反向代理或 Docker 网关的精确 IP/CIDR；默认空配置继续禁用转发头信任，避免客户端伪造来源地址。

增加逗号分隔的 `SERVER_TRUSTED_PROXIES` 部署变量，并在配置加载阶段规范化为代理列表。示例和部署文档只给出占位值，不写死生产网段。

主站访问接口仍始终返回 204，保证统计系统故障不影响浏览。但内部转发失败不再完全静默：记录不包含访客 ID、原始 IP、授权密钥的限流告警，包含失败阶段和 HTTP 状态类别，供部署排查。

## 部署完整性

生产部署顺序固定为：

1. 拉取不可变 Git SHA 镜像。
2. 解析主站与召回后台配置。
3. 运行召回数据库迁移。
4. 验证 `recall.SiteVisit` 表存在。
5. 验证至少一个 GeoIP 数据来源可用。
6. 验证主站配置了非全网的可信代理范围。
7. 启动或重建召回 Web、Worker 和主站服务。
8. 产生一次内部测试访问，确认 `SiteVisit` 行数增加并能解析国家。

增加访问链路预检命令，失败时返回非零退出码和不含秘密的明确原因。部署文档不得允许跳过迁移直接启动新镜像。

## 页面布局

访问趋势和四个 UV/PV 指标保持不变。地域区域调整为：

1. “访问 IP 国家或地区”与“中国大陆省份”并排，继续受时间范围控制。
2. “注册用户运营归因国家”作为独立全宽面板放在地域区域下方。
3. 两个国家表分别显示口径说明，避免管理员再次把用户归因当成实时访问来源。
4. 未知访问提示使用告警样式；普通口径说明使用中性说明样式。

本次不改变整体视觉设计系统、颜色和表格密度。

## 错误处理与安全

- 用户国家聚合失败时由页面现有错误边界处理，不回退到访问国家。
- GeoIP 状态读取失败按“不可用”处理，不暴露服务器路径以外的内容。
- 访问转发日志不记录原始 IP、访客 Cookie、内部密钥或请求正文。
- 可信代理配置拒绝空项、非法 IP/CIDR 和全网范围。
- 历史 `ZZ` 记录不自动回填；修复只保证新访问正确采集，旧数据保持原始事实。

## 测试策略

所有行为修改遵循测试驱动：先写失败测试，再实现最小修复。

1. 用户归因国家聚合正确合并国家、未识别值并排序。
2. 访问看板同时展示两套国家统计并显示正确口径说明。
3. 7、30、90 天切换只影响访问统计，不影响当前用户存量统计。
4. MMDB、RIR、HTTP 和完全未配置四种状态显示正确提示。
5. `SERVER_TRUSTED_PROXIES` 正确解析合法列表并拒绝非法或全网范围。
6. 可信代理测试证明代理请求使用真实客户端 IP，未配置时不信任伪造头。
7. 访问转发失败仍返回 204，并生成脱敏诊断日志。
8. 部署配置测试覆盖迁移、`SiteVisit` 表验证、GeoIP 和可信代理预检。
9. 现有访问 UV/PV、用户列表、权限控制和主站导航测试继续通过。

## 验收标准

- 管理员能在访问看板中分别看到“访问 IP 国家”和“注册用户运营归因国家”。
- 英国、新加坡等用户归因国家在用户统计中出现，不会被错误加入实时 IP 流量。
- 未知访问存在时，页面能区分 GeoIP 数据源缺失和正常查询未命中。
- 部署缺少 `SiteVisit` 迁移、GeoIP 来源或可信代理配置时会明确失败，而不是上线后静默漏数。
- 正常代理链下的新访问保存真实国家码；伪造转发头不能绕过可信代理限制。
- 访问采集故障不阻断主站页面，但日志足以定位转发失败阶段。
- 相关单元、集成、配置、类型检查、Lint 和生产构建全部通过。
