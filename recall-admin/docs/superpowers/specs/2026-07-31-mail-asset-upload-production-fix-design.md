# 生产邮件图片上传修复设计

## 问题

生产 Compose 没有向召回后台传递邮件资产存储变量。应用因此回退到 `local`，随后因生产环境禁止本地存储而抛出 `MAIL_ASSET_LOCAL_STORAGE_FORBIDDEN`。上传接口把该异常隐藏成通用 500，页面只显示“图片上传失败”。

## 范围

- 生产环境强制使用私有 S3 或 S3 兼容对象存储。
- 在生产 Compose、生产环境变量示例和部署文档中补齐全部映射。
- 启动时校验存储类型及必需参数，使错误在部署阶段暴露。
- 将存储配置异常转换为稳定的上传错误码，并给运营显示可行动提示。
- 保持现有图片范围：JPG、PNG、WebP；正文图片与图片附件共用同一存储。
- 不在本次加入 PDF、Word、Excel 等普通文件附件。

## 数据流

浏览器提交 multipart 图片后，上传接口进行权限与同源校验，图片标准化服务验证格式和大小，对象存储写入成功后再创建数据库记录。对象存储未配置或不可用时，接口返回 `MAIL_ASSET_STORAGE_UNAVAILABLE`，不写入数据库。

## 部署契约

生产环境必须设置 `RECALL_MAIL_ASSET_STORAGE=s3`，并提供 bucket、region、access key 和 secret key。endpoint 可留空以使用 AWS S3，也可填写兼容服务地址；force-path-style 默认为 `false`。

## 验证

- 环境解析测试覆盖生产缺失配置拒绝和完整 S3 配置接受。
- Compose 契约测试覆盖所有变量映射与生产示例。
- API 测试覆盖存储不可用错误码。
- 编辑器测试覆盖面向运营的中文提示。
- 完整单元测试、类型检查、代码规范和生产构建通过。
