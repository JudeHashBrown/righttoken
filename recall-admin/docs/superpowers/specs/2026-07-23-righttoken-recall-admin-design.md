# RightToken 用户跟踪与召回管理后台设计规格

> 状态：已完成书面确认，可进入实施
> 日期：2026-07-23  
> 首版规模：总用户少于 1 万，每日新增少于 500  
> 部署目标：RightToken 现有服务器，独立子域名 `recall.righttoken.ai`

## 1. 目标

将现有单文件 HTML 工具升级为可多人协作、可部署、可审计的真实管理后台。系统自动接收或校准 RightToken 用户状态，持续计算 A–G 分组，在需要人工介入时创建并分配运营任务，通过后台、企业微信群机器人和邮件提醒运营。

首版采用“自动管理、人工触达”原则：

- 系统自动同步用户、计算分组、迁移分组、创建任务、分配任务和升级提醒。
- 系统自动生成个性化邮件草稿，但必须由运营预览或修改后发送。
- 用户回复邮件后自动归档到用户时间线，并创建待回复任务。
- 系统不会在未经运营审核时向用户发送召回邮件。

## 2. 首版范围

首版交付以下能力：

1. 邮箱账号、密码和二次验证登录。
2. 唯一主管理员、多个管理员、多个运营人员。
3. 用户中心、用户 360 视图和完整事件时间线。
4. 可配置的 A–G 自动分组规则。
5. 可配置的任务触发、地区分配、优先级、SLA 和逾期升级。
6. 管理后台、企业微信群机器人和邮件三路运营提醒。
7. Namecheap 通用 SMTP/IMAP 邮箱和企业微信邮箱适配器。
8. 邮件草稿审核、发送、收取回复、退订和频率控制。
9. 转化、分组、任务、邮件、运营效率和渠道健康报表。
10. CSV 导入；仅主管理员可执行 CSV 导出。
11. 审计日志、失败重试、异常队列、健康监控和数据库备份。
12. 模拟数据、CSV 数据源和未来 RightToken 实时事件/全量校准接口。

首版不包含：

- 与 RightToken 正式数据库或网站源代码的实际连接；接口先完整保留。
- 未经人工审核的自动用户邮件。
- 短信、用户微信私聊或电话外呼。
- 自动创建优惠券、自动退款或自动修改用户余额。
- 微服务拆分或独立 Redis 集群。
- 对公众开放的移动端应用。

| 项目 | 决策 |

| 架构 | 轻量模块化单体 |
| 数据库 | PostgreSQL |
| 后台任务 | 独立任务进程，首版使用 PostgreSQL 承载任务队列 |
| 数据同步 | 实时事件 + 定时全量校准 |
| 用户触达 | 系统生成草稿，运营审核后发送 |
| 邮件回复 | 自动同步并关联用户 |
| 邮箱 | Namecheap SMTP/IMAP + 企业微信邮箱 |
| 运营提醒 | 后台 + 企业微信群机器人 + 邮件 |
| 任务分配 | 管理员可配置的优先级规则 |
| 权限 | 唯一主管理员 + 多管理员 + 多运营人员 |
| CSV 导出 | 仅主管理员 |
| 首页 | 运营驾驶舱 |
| 部署 | RightToken 服务器，`recall.righttoken.ai` |

## 4. 系统架构

系统由四个运行单元组成：

### 4.1 管理后台

提供登录、运营驾驶舱、用户、任务、邮件、自动化规则、报表、成员、权限和系统设置界面。

### 4.2 业务服务

负责：

- 用户快照和事件写入。
- A–G 分组计算与分组迁移。
- 任务创建、关闭、分配、转派和升级。
- 邮件草稿生成、发送校验和回复关联。
- 通知编排、权限判断和审计记录。

### 4.3 后台任务进程

负责：

- 注册满两小时等延时检查。
- RightToken 全量校准任务。
- IMAP 邮件收取。
- SMTP 发信。
- 企业微信群机器人和运营邮件通知。
- SLA 超时检查、失败重试和异常队列处理。
- 每日摘要、数据聚合和备份触发。

### 4.4 PostgreSQL

保存业务数据、事件、任务、邮件、规则、权限、审计和首版后台任务队列。业务应用与后台任务进程共享同一套领域接口，不直接在页面中拼接规则。

## 5. 模块边界

| 模块 | 职责 | 主要依赖 |
|---|---|---|
| 身份与权限 | 登录、邀请、二次验证、角色和会话 | 成员、审计 |
| 用户与事件 | 用户快照、原始事件、用户时间线、地区信息 | 数据源适配器 |
| 分组引擎 | A–G 计算、规则版本、迁移记录 | 用户与事件 |
| 任务中心 | 任务状态、SLA、领取、转派、关闭 | 分组、分配、通知 |
| 分配引擎 | 按地区等规则选择负责人 | 用户、成员、规则 |
| 邮件中心 | 草稿、发送、会话、回复、退订 | 邮箱适配器、任务 |
| 通知中心 | 后台、企微、邮件提醒和升级 | 任务、通知策略 |
| 报表 | 漏斗、分组、任务、邮件、团队和渠道指标 | 业务数据只读聚合 |
| 集成中心 | RightToken、CSV、邮箱、企微适配器 | 加密凭据 |
| 审计与导出 | 操作日志、导出授权和导出记录 | 身份与权限 |

每个模块通过明确的服务接口通信。适配器只负责外部协议转换，不包含分组或任务业务规则。

## 6. 数据接入与一致性

### 6.1 当前数据源

开发和验收阶段支持：

- 无真实个人信息的模拟数据。
- 管理员或主管理员上传 CSV。
- 现有管理台格式和 RightToken 后台原始导出格式的字段映射。

现有 HTML 中内嵌的真实邮箱和用户信息不得进入浏览器代码、测试夹具或版本库。真实数据只能通过受控导入进入数据库。

### 6.2 未来 RightToken 实时事件接口

统一事件至少包含：

```json
{
  "event_id": "唯一事件编号",
  "event_type": "user.registered",
  "occurred_at": "2026-07-23T10:00:00Z",
  "user_id": "RightToken 用户编号",
  "payload": {}
}
```

支持的事件类型包括：

- `user.registered`
- `checkout.started`
- `checkout.cancelled`
- `checkout.expired`
- `payment.failed`
- `payment.succeeded`
- `balance.changed`
- `api_call.succeeded`
- `service.anomaly`
- `service.recovered`
- `complaint.created`
- `refund.requested`
- `user.profile_updated`

`event_id` 用于幂等去重。`occurred_at` 用于处理乱序事件。事件写入后由分组引擎重新计算用户当前分组。

### 6.3 定时全量校准

RightToken 适配器提供按更新时间分页读取用户快照的能力。默认每 15 分钟执行增量校准，每日凌晨执行一次完整校准。管理员可以调整周期。

校准规则：

- 外部事实字段以 RightToken 为准。
- 运营任务、邮件、负责人、原因标签和审计记录以本系统为准。
- 校准只修复用户事实，不覆盖运营记录。
- 同一快照不会重复创建任务。

## 7. 用户快照与事件时间线

用户快照至少保存：

- 外部用户编号、邮箱、称呼、注册时间。
- 注册 IP 的加密值、国家、地区、语言和时区。
- 注册来源渠道。
- 是否进入支付、最近支付状态、首付时间和充值累计。
- 是否成功调用、首次调用、最后调用和调用计数。
- 当前余额和最近余额变化时间。
- 是否存在投诉、退款、连续错误或服务异常。
- 当前分组、分组版本、负责人和最后事件时间。
- 是否退订、暂停或禁止联系。

事件时间线保存所有外部事件、分组迁移、任务动作、邮件和人工备注。运营记录不能被外部校准覆盖。

## 8. A–G 自动分组

分组按以下顺序计算，前一条件命中后不再继续：

1. **F 服务异常**：存在未解除的投诉、退款、连续调用失败或服务异常。
2. **未成功首付用户**：
   - 进入过支付流程则为 **B 支付未完成**。
   - 未进入支付流程则为 **A 注册未支付**。
3. **C 已充值未调用**：已成功充值但没有成功 API 调用。
4. **E 余额耗尽未复充**：有成功调用历史且当前余额小于或等于配置阈值。
5. **D 调用后停用**：有成功调用历史、余额高于阈值，最后调用距今达到配置天数。
6. **G 正常活跃/复购**：不符合以上条件的健康用户。

默认阈值：

| 条件 | 默认值 | 任务行为 |
|---|---:|---|
| A 注册未支付观察期 | 2 小时 | 观察期后仍未首付，创建普通任务 |
| B 进入支付未完成 | 30 分钟 | 仍未支付，创建重要任务 |
| C 充值后未调用 | 24 小时 | 仍未调用，创建重要任务 |
| D 停用天数 | 7 天 | 创建普通任务 |
| E 余额耗尽观察期 | 3 天 | 仍未复充，创建普通任务 |
| F 服务异常 | 立即 | 创建紧急任务 |
| G 健康用户 | 不创建个人召回任务 | 仅用于统计和经批准的内容培育 |

管理员可以调整阈值、任务级别、是否创建任务和对应邮件模板。每次发布规则会生成新版本，并记录操作人和变更内容。

分组由系统计算，不能无审计地直接手改。管理员如需纠正，必须修正事实字段或创建有原因的临时例外；例外包含失效时间。

## 9. 分组迁移和任务幂等

用户事实变化后，系统执行：

1. 写入唯一事件。
2. 更新不早于当前快照的事实字段。
3. 用当前生效规则重新计算分组。
4. 分组变化时写入迁移记录。
5. 关闭因旧分组而失效的未完成自动任务，关闭原因为“分组变化”。
6. 根据新分组和观察期创建新的延时检查或运营任务。
7. 运行分配规则并发送对应级别的运营提醒。

自动任务使用“用户 + 触发规则 + 触发窗口 + 规则版本”组成唯一键，确保重复事件和重复校准不会生成重复任务。

人工任务不会因分组变化自动删除；系统会标记上下文已变化，由负责人决定关闭或继续。

## 10. 任务分配规则

管理员通过有顺序的规则列表配置任务分配。可用条件包括：

1. 国家、地区、注册 IP 段。
2. 用户语言和时区。
3. 注册来源渠道。
4. 当前 A–G 分组。
5. 充值金额或用户价值等级。
6. 运营工作时间。
7. 运营当前未完成任务量。

每条规则包含名称、状态、优先级、条件、目标负责人或目标任务池、负载上限和生效时间。

匹配流程：

- 从上到下匹配第一条满足条件的规则。
- 负责人不可用或超过负载上限时，按规则的后备负责人处理。
- 没有规则命中时进入默认公共任务池。
- 管理员保存规则前，可以用最近历史用户预览分配结果和未匹配比例。
- 每个任务显示“分配原因”。
- 管理员和当前负责人可以转派，必须填写原因。

## 11. 任务中心与 SLA

任务状态：

- 待领取
- 待处理
- 处理中
- 等待用户
- 已完成
- 已暂停
- 已取消

任务视图：

- 我的任务
- 公共任务池
- 待回复
- 已逾期
- 全部任务

默认提醒策略：

| 级别 | 示例 | 首次提醒 | 默认升级 |
|---|---|---|---|
| 紧急 | F 服务异常 | 后台 + 企微群 + 邮件，立即 | 15 分钟无人领取再次提醒；30 分钟升级主管理员 |
| 重要 | B 支付未完成、C 未调用、用户回复 | 后台 + 企微群，立即 | B/C 默认 2 小时、用户回复默认 4 小时；超时后企微 + 邮件升级管理员 |
| 普通 | A 未支付、D 停用、E 未复充 | 后台立即展示，每天 10:00 汇总到企微群 | 默认 1 个工作日；超时后企微 + 邮件升级管理员 |

管理员可修改每个触发规则的级别、SLA、提醒渠道、重试间隔和升级对象。

企微群消息只包含脱敏用户编号、国家/地区、分组、触发原因、剩余时限和后台任务链接。

## 12. 邮件闭环

### 12.1 邮件适配器

系统定义统一邮箱接口：

- 发送邮件。
- 读取指定时间后的新邮件。
- 获取发送状态。
- 验证连接。

首版适配器：

- Namecheap Private Email：加密 SMTP 发送、IMAP 收取。
- 企业微信邮箱：按其提供的 SMTP/IMAP 或管理员配置接入。

凭据只加密保存在服务端，不传给浏览器，不写入日志。

### 12.2 草稿与发送

1. 任务生成后按分组、触发原因和用户语言选择模板。
2. 系统填充称呼、负责人、链接等允许变量。
3. 运营预览或编辑草稿。
4. 服务端在发送前校验退订、暂停、频率上限、重复触达和必填变量。
5. 运营点击发送。
6. 系统记录最终正文版本、发送人、时间、邮箱通道和消息编号。

模板发布由管理员完成。模板修改保留版本，历史邮件保持发送时内容。

### 12.3 回复同步

- 后台任务进程持续从 IMAP 收取新邮件。
- 优先通过 `Message-ID`、`In-Reply-To` 和 `References` 关联会话。
- 其次通过收发件人和时间窗口匹配。
- 成功关联后写入用户时间线，创建“待回复”重要任务。
- 无法可靠关联的邮件进入人工归档箱，不自动绑定用户。

### 12.4 退订与频率

- 退订立即写入全局禁止联系名单。
- 被退订用户不能通过普通页面发送邮件。
- 频率限制在服务端强制执行。
- 管理员可配置不同分组的最短联系间隔。
- 打开和点击跟踪为可选功能，默认关闭；启用时在模板和隐私策略中明确披露。

## 13. 权限模型

系统同时只允许一个主管理员，但允许多个管理员和运营人员。

### 13.1 主管理员

- 拥有全部系统权限。
- 设置、撤销多个管理员。
- 管理运营人员、集成凭据和全部规则。
- 唯一可以导出 CSV。
- 可以转移主管理员身份。

### 13.2 管理员

- 配置分组、分配、通知和邮件模板。
- 邀请、停用和管理运营人员。
- 查看全部用户、任务、报表和审计记录。
- 导入 CSV。
- 不能导出 CSV。
- 不能修改、停用或移除主管理员。
- 不能授予或撤销管理员身份。

### 13.3 运营人员

- 查看被授权的用户与任务。
- 领取、处理、转派获准任务。
- 编辑并发送邮件，处理用户回复。
- 添加运营备注和原因标签。
- 不能修改规则、成员、集成或系统设置。
- 不能批量导入或导出数据。

## 14. CSV 导出保护

CSV 导出只允许主管理员执行，并同时满足：

1. 服务端确认当前角色为主管理员。
2. 导出前重新验证密码或二次验证。
3. 主管理员明确选择时间范围、用户范围和字段。
4. 文件中敏感字段按选择和业务必要性输出。
5. 写入导出人、时间、筛选范围、字段、记录数和文件摘要。
6. 下载链接短期有效且只能使用一次。

页面隐藏导出按钮不能替代服务端权限校验。管理员和运营直接调用导出接口必须返回拒绝。

## 15. 登录与账号安全

- 账号只能由主管理员或管理员邀请。
- 密码采用行业标准的慢哈希算法保存。
- 二次验证使用身份验证器动态口令，并提供一次性恢复码。
- 主管理员必须启用二次验证。
- 管理员默认要求启用二次验证；主管理员可将其设为强制。
- 登录、导出、角色变更、邮箱凭据修改和主管理员转移需要重新验证。
- 连续失败登录会限速并触发安全告警。
- 会话支持主动退出、管理员强制失效和设备列表。

主管理员转移需要当前主管理员重新验证并明确确认。转移完成后旧主管理员自动降为管理员，系统保证任意时刻恰好一个主管理员。

## 16. 敏感数据与审计

- 浏览器不保存完整用户数据到 localStorage。
- 所有访问通过服务端权限校验。
- 传输使用 HTTPS。
- 注册 IP 和集成凭据加密保存。
- 完整注册 IP 默认保留 180 天，到期后只保留国家、地区和不可逆摘要；主管理员可以缩短保留期。
- 运营在其被授权的用户范围内可以查看完整邮箱。
- 用户列表显示完整邮箱但不返回注册 IP；用户 360 详情页向有权访问该用户的运营、管理员和主管理员显示完整注册 IP。
- 审计日志和跨用户汇总仍默认脱敏邮箱与 IP，避免在非用户操作场景扩散敏感信息。
- 审计日志记录查看敏感详情、发信、转派、导入、导出、规则、成员、凭据和权限操作。
- 审计记录不允许普通用户修改或删除。
- 默认保留业务审计记录 2 年；主管理员可设置更长保留期。

## 18. 报表

报表支持时间、地区、来源、分组、负责人和任务级别筛选。

核心报表：

1. 注册 → 进入支付 → 首付 → 首次调用 → 持续活跃漏斗。
2. A–G 当前分布和分组迁移趋势。
3. 各分组任务创建、完成和召回转化率。
4. 任务领取时间、首次响应时间、完成时间和逾期率。
5. 团队与运营个人任务负载和处理效率。
6. 邮件发送、失败、回复、退订和可选打开/点击数据。
7. 邮箱、企微、数据同步和任务队列健康状态。
8. 常见原因标签和用户反馈摘要。

主管理员可将当前筛选结果导出 CSV。管理员和运营只能在线查看其权限范围内的报表。

## 19. 异常处理

### 19.1 外部事件

- 重复事件直接返回已处理结果。
- 旧事件保留在时间线，但不能覆盖更新的用户事实。
- 不合法事件进入隔离记录，并返回明确错误。
- 连续接入失败触发管理员告警。

### 19.2 邮件和企微

- 短暂失败按指数退避重试。
- 达到重试上限后进入异常队列。
- 管理员可以查看错误、测试连接和人工重试。
- SMTP 发送状态不明确时先查询或人工确认，避免重复发送。
- IMAP 无法关联的邮件进入人工归档箱。

### 19.3 规则和任务

- 规则发布前校验冲突、空负责人和不可达分支。
- 规则预览显示受影响用户数和分配结果。
- 发布后使用新版本处理新事件；已有任务不被静默改写。
- 后台任务进程中断后可从数据库继续处理未完成任务。

## 20. 监控、备份与恢复

- 首页显示外部数据、邮箱、企微和任务队列健康状态。
- 监控任务积压、最老任务等待时间、最近成功同步和失败次数。
- 数据库每日自动备份，默认保留 30 天。
- 上线前执行一次完整恢复演练。
- 恢复演练记录恢复时间、数据完整性和待补发任务。
- 部署使用容器，应用和任务进程可以独立重启。
- 反向代理负责 HTTPS、请求大小限制和基础限流。

## 21. 验收场景

首版至少通过以下端到端场景：

1. 新用户注册后立即进入 A，满 2 小时仍未支付时生成普通任务并按地区分配。
2. 用户在观察期内进入支付，旧 A 延时任务失效，30 分钟未支付时进入 B 并生成重要任务。
3. B 用户支付成功后进入 C，旧 B 任务自动关闭。
4. C 用户 24 小时未调用时生成接入帮助任务；首次调用后进入 G。
5. 有余额用户 7 天未调用时进入 D；重新调用后回到 G。
6. 余额耗尽 3 天未复充时创建 E 任务；复充后自动重新分组。
7. 任意用户发生投诉或连续报错时立即进入 F，并触发紧急三路提醒；异常解除事件到达后重新计算正常分组。
8. 重复或乱序事件不会重复建任务或回退用户事实。
9. 地区规则命中正确负责人；负责人超负载时使用后备规则。
10. 运营编辑草稿并发送，最终内容和发送人写入审计。
11. 用户回复自动关联会话并创建待回复任务。
12. 退订用户无法再次发送普通召回邮件。
13. Namecheap、企业微信邮箱或企微失败时自动重试并进入异常队列。
14. 运营和管理员调用 CSV 导出接口被拒绝。
15. 主管理员重新验证后成功导出，导出行为写入审计。
16. 主管理员转移后系统仍恰好只有一个主管理员。
17. 数据库备份可以在隔离环境中恢复，用户、任务、邮件和审计记录一致。

## 22. 部署形态

1. RightToken 实时事件发送器。
2. RightToken 全量校准适配器。
3. 字段映射和身份关联配置。
4. 必要的单点登录或后台导航入口。

分组、任务、邮件、通知、权限、报表和现有页面保持不变。正式切换前使用影子同步对比分组结果，确认一致后再启用生产任务提醒。
