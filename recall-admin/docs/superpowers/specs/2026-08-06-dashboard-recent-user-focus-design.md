# 仪表盘近 72 小时用户焦点设计

## 目标

让仪表盘首页直接回答两个运营问题，并支持在当前页面下钻查看用户：

1. 最近 72 小时注册但尚未支付的用户有哪些。
2. 最近 72 小时发生服务异常的用户有哪些。

同时删除无操作价值的首页标题、问候语和日期区域。

## 展示与交互

- 删除“用户运营概览”、问候语和右上角日期组成的整个页头。
- 第一张指标卡改为“近72小时注册未支付”。
- 第二张指标卡改为“近72小时服务异常”。
- 两张卡片均为站内链接。点击后仍停留在 `/dashboard`，通过 `focus` 查询参数选择内容，并定位到指标卡下方的焦点用户列表。
- 注册未支付链接：`/dashboard?focus=recent-unpaid#focus-list`。
- 服务异常链接：`/dashboard?focus=recent-anomaly#focus-list`。
- 彻底删除“优先任务”概念、列表及其仪表盘数据查询。
- 没有 `focus` 参数时默认选择“近72小时服务异常”，并在原“优先任务”所在的左侧主面板展示服务异常用户。
- 点击任一指标卡时，原位置在“注册未支付用户”和“服务异常用户”之间切换；页面只保留这一处焦点列表，不重复渲染第二份下钻列表。
- 保留用户分组、渠道与团队工作量区域。
- 焦点列表为空时展示清晰空状态。

## 取数口径

所有查询均沿用仪表盘既有权限范围：主管理员可见全部用户；运营人员只可见归属自己或尚未分配的用户。已从来源删除的用户不计入统计，也不进入列表。

### 近72小时注册未支付

- `currentSegment = A`（注册未支付）。
- `registeredAt >= 当前时间 - 72 小时`，边界时刻包含在内。
- `sourceDeletedAt IS NULL`。

列表按注册时间从新到旧排列，展示用户、邮箱、地区、注册时间、负责人。

### 近72小时服务异常

- `currentSegment = F`（服务异常）。
- `anomalyActive = true`。
- `anomalyLastOccurredAt >= 当前时间 - 72 小时`，或在缺少/晚于该字段时以 `anomalyChangedAt >= 当前时间 - 72 小时` 判断。
- `sourceDeletedAt IS NULL`。

列表使用两个异常时间字段中的较晚者作为“异常时间”，按该时间从新到旧排列，展示用户、邮箱、异常原因、异常时间、负责人。

## 数据与接口设计

- `DashboardSnapshot.metrics` 新增 `recentUnpaid` 与 `recentAnomalies`，保留原任务指标供全局导航徽标继续使用。
- `DashboardSnapshot` 新增可空的 `focus` 和 `focusUsers`。
- `getDashboardSnapshot(member, now, focus)` 加载对应焦点的用户明细；页面未传焦点时使用 `recent-anomaly`。
- 页面只接受 `recent-unpaid`、`recent-anomaly` 两种 `focus` 值，其他值按未选择处理。
- 明细展示只使用本地 `UserProfile` 与负责人关联，避免为列表引入额外外部请求。
- 明细列表最多加载最近 100 位用户，面板同时展示完整指标总数，避免高峰期返回无界数据。
- 全站布局改用独立的轻量导航指标查询，不再为了侧边栏与顶栏加载完整仪表盘数据。

## 非目标

- 不改变用户分组规则。
- 不修改用户状态、负责人或任务状态。
- 不删除任务中心本身、任务快捷筛选能力及导航徽标口径；只删除仪表盘首页的优先任务模块。
- 不推送 GitHub。

## 验证

- 单元测试覆盖 72 小时边界、角色权限范围、已删除来源排除和异常时间回退逻辑。
- 组件测试覆盖页头和优先任务删除、新卡片文案与链接、默认异常列表、两种列表及空状态。
- 运行完整单元测试、集成测试、代码规范、类型检查与生产构建。

## 自检

- 两个指标均有明确、可复用且与列表一致的查询条件。
- 点击行为在当前页面完成，不引入审批或数据变更。
- 原导航通过轻量查询读取旧任务指标，不因卡片换义产生回归。
- 设计未包含占位项或未决策内容。
