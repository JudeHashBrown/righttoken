# GeoIP 地域负责人分配设计

## 目标

用户注册时，系统使用注册 IP 解析国家和省 / 州 / 地区，并将用户和后续召回任务自动分配给对应运营负责人。

## 业务规则

1. 注册事件中的 IP 是地域解析输入。
2. 若注册事件已经携带可信的国家或地区，则保留已有值，只补全缺失字段。
3. 地区规则以省 / 州 / 地区为最小粒度，优先于国家规则。
4. 地区规则未命中时匹配国家规则。
5. 主要负责人不可用时使用后备负责人；仍不可用时进入公共任务池。
6. IP 缺失、私网 IP、解析失败或服务不可用时，注册流程仍然成功，用户进入“地区待识别”状态并可在后续同步中补全。
7. GeoIP 服务不得接收用户邮箱、姓名、支付信息或其他业务数据，只发送 IP。

## 架构

### GeoIP 适配层

新增 `GeoIpResolver` 接口：

```ts
type GeoIpLocation = {
  countryCode: string | null;
  region: string | null;
};

type GeoIpResolver = {
  resolve(ip: string): Promise<GeoIpLocation | null>;
};
```

默认实现读取环境变量配置的 HTTP GeoIP 服务。未配置服务时使用禁用实现并返回 `null`，不影响注册。

### 用户数据写入

注册事件写入前调用解析器：

- 已有 `country_code` 时不覆盖。
- 已有 `region` 时不覆盖。
- 仅使用解析结果补全空字段。
- 解析异常被捕获并记录为未解析，不回滚注册事件。

### 分配规则

现有规则结构继续使用：

- `countryCodes`: ISO 3166-1 alpha-2 国家代码。
- `regionIncludes`: 省 / 州 / 地区名称。
- `assigneeId`: 主要负责人。
- `fallbackAssigneeId`: 后备负责人。

匹配顺序：

1. 启用且命中地区的规则。
2. 启用且命中国家的规则。
3. 其他已配置规则。
4. 公共任务池。

同一层级内继续按管理员设置的优先级匹配。

## 配置

```env
GEOIP_HTTP_URL=
GEOIP_HTTP_TOKEN=
GEOIP_HTTP_TIMEOUT_MS=2000
```

请求地址支持 `{ip}` 占位符。响应必须包含：

```json
{
  "countryCode": "CN",
  "region": "广东省"
}
```

## 测试

- 公网 IP 能解析并补全国家和地区。
- 已有国家或地区不会被覆盖。
- 私网 IP 不调用外部服务。
- 超时和异常不阻断注册。
- 地区规则优先于国家规则。
- 国家规则在没有地区规则时正常命中。
- 未命中时进入公共池。

## 非目标

- 不在首版维护全球国家、省份字典。
- 不在首版购买或绑定具体 GeoIP 供应商。
- 不根据 GPS、浏览器定位或邮箱域名推断地区。
