# 运营归属地判定设计

## 目标

为 RightToken 内部运营分配建立一套低成本、可解释、可重新计算的用户归属地判定机制。归属地只用于分配运营负责人，不声明用户的真实所在地或国籍。

## 已确认规则

1. 邮箱证据优先于注册 IP。
2. 完整邮箱域名优先于国家域名后缀。
3. 邮箱未命中时，使用本地 IP 地址段数据库。
4. 精细 GeoIP 未命中时，使用 RIR 地址段登记国家兜底。
5. VPN、代理和云服务器不单独识别，始终按注册时看到的公网出口 IP 判断。
6. 有效公网 IP 的正常注册流程必须产生运营归属地；数据缺少或损坏时交给系统默认负责人，不进入公共池。
7. 邮箱覆盖 IP 国家时，最终运营地区置空，避免产生国家与省州互相冲突的数据。

## 数据模型

`UserProfile.countryCode` 和 `UserProfile.region` 继续表示最终的运营归属地，避免修改现有查询、分组和任务分配接口。

新增原始证据字段：

- `ipCountryCode`: 本地 IP 数据库或 RIR 地址段得到的国家代码。
- `ipRegion`: 本地 IP 数据库得到的省、州或地区。
- `locationSource`: 最终运营归属地的判定来源。
- `locationRuleId`: 命中的邮箱规则；IP 判定时为空。
- `locationEvaluatedAt`: 最近一次判定时间。

新增 `LocationAttributionRule`：

- `name`
- `enabled`
- `priority`
- `matchType`: `EXACT_DOMAIN` 或 `DOMAIN_SUFFIX`
- `pattern`
- `countryCode`
- `createdAt` / `updatedAt`

完整域名和后缀均使用小写 ASCII 形式保存。国际化域名在比较前转为 ASCII/Punycode。

## 默认邮箱规则

### 完整域名

- 中国：`qq.com`、`vip.qq.com`、`foxmail.com`、`163.com`、`126.com`、`yeah.net`、`sina.com`、`sina.cn`、`sohu.com`
- 俄罗斯：`mail.ru`、`inbox.ru`、`list.ru`、`bk.ru`、`internet.ru`、`yandex.ru`、`ya.ru`、`rambler.ru`
- 白俄罗斯：`yandex.by`、`mail.by`
- 哈萨克斯坦：`mail.kz`、`yandex.kz`
- 乌兹别克斯坦：`umail.uz`
- 吉尔吉斯斯坦：`kmail.kg`

### 国家后缀

- 俄罗斯、白俄罗斯、中亚、高加索：`.ru`、`.рф`、`.by`、`.бел`、`.kz`、`.kg`、`.uz`、`.tj`、`.tm`、`.am`、`.az`、`.ge`
- 美国：`.us`
- 欧洲：采用 IANA 国家代码域名，包括 `.uk`、`.ie`、`.de`、`.at`、`.ch`、`.li`、`.fr`、`.be`、`.nl`、`.lu`、`.it`、`.es`、`.pt`、`.gr`、`.mt`、`.cy`、`.se`、`.no`、`.dk`、`.fi`、`.is`、`.pl`、`.cz`、`.sk`、`.hu`、`.ro`、`.bg`、`.si`、`.hr`、`.rs`、`.ba`、`.mk`、`.al`、`.ee`、`.lv`、`.lt`、`.ua`、`.md`
- `.eu` 只映射到欧洲区域标识，不冒充某个具体国家；负责人规则可直接匹配欧洲区域。

以下跨国使用域名不自动映射：`.com`、Gmail、Outlook、Hotmail、Yahoo、Proton、`.edu`、`.gov`、`.mil`、`.ai`、`.io`、`.co`、`.me`、`.tv`、`.fm`、`.cc`、`.su`。

## 判定流程

1. 验证并标准化邮箱域名。
2. 按优先级匹配启用的完整域名规则。
3. 未命中时按优先级匹配启用的国家后缀规则。
4. 查询本地 GeoIP City MMDB，得到国家和地区。
5. GeoIP 未命中时查询本地 RIR 地址段索引，得到登记国家。
6. 邮箱命中时：
   - `countryCode = 邮箱规则国家`
   - `region = null`
   - 保存 IP 原始国家和地区
7. 邮箱未命中时：
   - `countryCode = ipCountryCode`
   - `region = ipRegion`
8. 缺少或损坏 IP 时记录数据异常，并将后续任务交给系统默认负责人。

数据库和外部文件读取失败不得阻塞用户注册。注册事件先保留，随后可以通过重算任务补全归属地。

## 本地 IP 数据

- 首选 `GeoLite2-City.mmdb`，进程内只打开一次并复用读取器。
- 保留现有 HTTP GeoIP 适配器作为可选备用，不作为默认路径。
- RIR 地址段使用本地快照并按开始地址排序，通过二分查找匹配 IPv4/IPv6。
- 数据文件不提交进 Git；容器通过只读卷挂载。
- GeoLite 与 RIR 快照由独立更新脚本定期刷新，失败时保留上一版。

## 管理界面

分配规则页面新增紧凑的“邮箱归属规则”区域，只展示运营需要操作的内容：

- 匹配内容
- 匹配方式
- 归属国家
- 启用状态
- 优先顺序

不在前端展示数据库格式、内部算法描述或设计文档语言。主管理员可以新增、修改、停用、排序和发布。发布时可选择预览影响人数，确认后全量重算。

用户详情显示：

- 运营归属国家和地区
- 判定来源（邮箱规则或注册 IP）
- IP 原始国家和地区

## 全量重算

发布邮箱归属规则后创建后台重算任务。重算：

- 使用保存的加密注册 IP 和当前邮箱。
- 更新运营归属地和负责人。
- 保留原始事件与历史任务。
- 写入审计日志。
- 失败用户单独记录并重试，不回滚已成功用户。

## 测试

必须覆盖：

- 俄罗斯 IP + QQ 邮箱归中国。
- 香港 IP + 普通 `.com` 邮箱归香港。
- `.ru` 邮箱覆盖其他国家 IP。
- 完整域名优先于后缀。
- 邮箱大小写、空白和国际化域名标准化。
- 被排除的全球通用域名不覆盖 IP。
- GeoIP 未命中时使用 RIR 国家。
- 缺少或损坏 IP 时返回默认负责人路径。
- 规则发布预览、全量重算和审计记录。
- 旧用户迁移后仍保留现有运营国家和地区。

## 非目标

- 不识别用户是否使用 VPN。
- 不追求街道或个人级精度。
- 不根据邮箱推断国籍、合规身份或真实居住地。
- 首版不购买商业 GeoIP API。
