# 邮件受众与隐私安全群发设计

## 目标

邮件中心的“写邮件”支持三种发送对象：

1. 指定一个用户；
2. 指定 F、A、B、C、D、E、G 中的一个用户分组；
3. 当前权限范围内的全部用户。

分组和全员发送必须逐个收件人独立投递。每封邮件的 `To` 只能包含当前收件人的邮箱，不使用 `CC`、公开收件人列表或包含多人的 `To`，确保收件人无法看到其他用户邮箱。

## 非目标

- 本期不支持一次选择多个分组；
- 本期不增加任意邮箱列表导入；
- 本期不实现按用户字段个性化替换正文变量；
- 本期不改变现有单人邮件允许人工确认最终收件邮箱的行为；
- 本期不使用 BCC 作为群发实现。

## 用户体验

### 发送对象

“写邮件”表单顶部增加“发送对象”选择：

- `指定用户`：保留现有搜索用户、选择用户、关联任务和最终收件人功能；
- `指定分组`：显示 F、A、B、C、D、E、G 分组选择；
- `全部用户`：选择当前操作者有权联系的全部有效用户。

分组和全员模式隐藏单人任务选择与最终邮箱编辑，显示受众摘要：

- 受众名称；
- 预计用户数；
- 自动跳过规则；
- “每位用户将收到独立邮件，无法看到其他收件人邮箱”的隐私说明。

发送按钮文案根据模式变化：

- 单人：`确认并发送`；
- 分组/全员：`确认创建群发`。

### 发送结果

提交群发后显示批次状态和以下计数：

- 待处理；
- 发送成功；
- 已跳过；
- 发送失败。

跳过和失败按安全的原因代码汇总，不在列表或审计日志中暴露完整邮箱。运营人员可以针对失败项发起重试；成功和已跳过的收件人不重复发送。

邮件中心增加群发批次列表。单封成功邮件仍出现在“已发送”邮件列表，并与对应用户、邮件会话和跟进任务关联。

## 受众规则

### 权限范围

管理员和主管可以覆盖全部有效用户。运营人员只覆盖：

- 负责人是自己的用户；
- 尚未分配负责人的用户。

这与现有主动联系用户的权限边界保持一致。服务端必须重新解析权限和受众，不能信任浏览器提交的收件人列表。

### 固定快照

创建批次时，服务端根据发送模式解析用户，生成不可变的批次收件人快照。之后即使用户分组或负责人发生变化，本批次仍按创建时已经记录的用户集合处理，避免名单漂移。

有效用户必须满足：

- `sourceDeletedAt` 为空；
- 邮箱格式有效；
- 在操作者权限范围内；
- 分组模式下 `currentSegment` 等于所选分组。

同一个规范化邮箱在一个批次内只发送一次。重复邮箱的其他用户记录标记为跳过，原因是 `DUPLICATE_RECIPIENT`。

### 跳过规则

以下情况不阻断整个批次，只跳过对应用户：

- 用户已退订；
- 邮箱在抑制名单中；
- 用户处于暂停联系状态；
- 不满足最短联系间隔；
- 邮箱格式无效；
- 同批次规范化邮箱重复；
- 后台执行前用户已被源系统删除。

受众预览数是创建前估算；最终成功、跳过和失败数以固定快照的执行结果为准。

## 架构

### 数据模型

新增 `MailBatch`，记录：

- 发件邮箱、创建人；
- 发送模式 `USER`、`SEGMENT` 或 `ALL`；
- 可选的用户 ID、分组代码；
- 主题、纯文本和 HTML 正文；
- 批次状态；
- 总数、待处理、成功、跳过和失败计数；
- 创建、开始和完成时间。

新增 `MailBatchRecipient`，每行对应一个快照用户，记录：

- 批次 ID、用户 ID 和规范化邮箱；
- `PENDING`、`SENDING`、`SENT`、`SKIPPED` 或 `FAILED` 状态；
- 安全原因代码；
- 成功后关联的邮件、会话和任务；
- 尝试次数、最近尝试时间和完成时间。

批次与用户的唯一约束防止同一用户重复入列。创建快照的同一事务按规范化邮箱选出一个可发送记录，其余重复记录立即标记为 `SKIPPED`；worker 只领取 `PENDING` 记录，因此同一批次不会向重复邮箱投递。

### 服务边界

`mail-audience` 模块负责：

- 校验发送对象；
- 按操作者权限预览数量；
- 创建固定收件人快照。

`mail-batch-service` 模块负责：

- 创建批次；
- 原子领取待处理收件人；
- 更新计数和最终状态；
- 只重试失败收件人。

现有 `sendReviewedMail` 继续作为单收件人发送核心。后台处理器对每个快照收件人单独调用它，保证现有权限、退订、频率限制、邮件资产、审计、任务和会话逻辑继续生效。

### 后台任务

新增 pg-boss 任务类型处理邮件批次。每次领取有限数量的待处理收件人，逐个投递，再调度下一批，避免单个任务长时间占用 worker。

领取操作必须具备幂等性：

- 已成功或已跳过的记录不再领取；
- 发送成功后保存消息 ID；
- worker 重试时先检查收件人状态和消息关联；
- 一个收件人的失败不回滚其他收件人的成功。

### 邮件隐私

每次 SMTP 调用必须满足：

```text
to = [当前收件人邮箱]
cc = 不设置
bcc = 不设置
```

数据库中的每条 `MailMessage.toAddresses` 也只能保存该封邮件的单一收件人。任何接口响应、批次列表和审计元数据不得返回或记录整批完整邮箱列表。

## API

### 受众预览

`GET /api/mail/audience-preview`

参数：

- `mode=SEGMENT&segment=F`；
- 或 `mode=ALL`。

返回受众名称、预计总数和预计跳过数，不返回邮箱列表。

### 创建发送

保留 `POST /api/mail/send` 处理单人发送。

新增 `POST /api/mail/batches` 处理分组和全员发送，请求包含：

- `mode`；
- 可选 `segment`；
- `mailboxId`；
- 主题、正文和图片资产引用。

响应返回批次 ID 和初始计数，不同步等待整批发送完成。

### 查询和重试

- `GET /api/mail/batches`：批次摘要列表；
- `GET /api/mail/batches/:id`：单个批次状态与原因汇总；
- `POST /api/mail/batches/:id/retry`：只将失败收件人重新入列。

## 错误处理

- 请求无权限、邮箱未启用、发送对象无效或受众为空：拒绝创建批次；
- 邮件资产无效：在创建批次前拒绝，避免整批失败；
- 单个用户被发送保护规则拦截：标记为跳过；
- SMTP 临时或永久错误：标记为失败并保留安全错误代码；
- worker 中断：未完成记录保持可恢复状态，超时的 `SENDING` 记录可被重新领取；
- 计数由收件人状态聚合或在事务内更新，不能出现总数与各状态之和不一致。

## 测试

### 单元测试

- 请求结构只接受三种合法发送模式；
- 权限范围和分组条件正确；
- 预览只返回计数，不返回邮箱；
- 同批次重复邮箱只保留一个可发送项；
- SMTP 输入始终只有一个 `to`，且没有其他收件人字段；
- 组件在三种发送模式间正确切换并生成正确请求；
- 群发模式不能编辑最终邮箱或关联单人任务。

### 集成测试

- 分组批次只快照目标分组和权限范围内用户；
- 全员批次包含全部权限范围内有效用户；
- 退订、暂停、频率受限和无效邮箱被跳过，其他用户继续；
- 每位成功收件人产生独立 `MailMessage`、`MailThread` 和 `RecallTask`；
- 单个 SMTP 失败不影响其他收件人；
- worker 重试不会重复投递已成功用户；
- 失败重试只处理失败项；
- 批次计数和状态最终一致。

### 界面验收

- localhost 邮件中心可以选择指定用户、指定分组或全部用户；
- 分组和全员模式清楚显示预计人数及隐私说明；
- 创建群发后能看到批次进度；
- 已发送列表中每封邮件只展示一个收件人；
- 现有单人发送、回复邮件、模板和图片功能不回归。

## 完成标准

- 用户可以向具体个人、一个完整分组或全部有效用户发邮件；
- 群发邮件逐人独立投递，任何收件人都看不到其他邮箱；
- 不合规用户自动跳过并展示汇总；
- 群发过程可恢复、可追踪、可安全重试且不会重复发送；
- 单人发送及现有邮件中心能力保持兼容。
