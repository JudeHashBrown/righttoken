# A–G 互斥分组规则编辑器设计

## 背景与目标

当前“分组规则”页面只允许修改少量时间和余额参数，并把“进入分组的条件”与“多久后提醒运营”混在同一组输入框中。管理员无法看到每个分组的完整定义，也无法通过界面重新组合字段和条件。

本次升级要把页面改造成结构化规则编辑器：

- A、B、C、D、E、F、G 是固定主名称，不能新增、删除或重命名；
- 每个分组提供一段可编辑注释，解释该组的业务含义；
- 管理员通过“字段、运算符、值”配置条件，不需要编写代码；
- 同一个用户最终只能进入一个分组；
- 发布前预览规则冲突、分组变化和任务影响；
- 发布后使用新版本重新计算系统内全部用户；
- 保留历史版本、迁移原因、审计记录和回滚能力。

现有 A–G 业务逻辑作为首个完整规则集的默认值，升级过程不主动改变当前用户的业务分类结果。

## 权限

沿用当前权限边界：

- 主管理员和具有 `rules:publish` 权限的普通管理员可以编辑、预览、发布和回滚分组规则；
- 运营可以查看当前生效规则，但不能修改或发布；
- 所有预览、发布、回滚和全量重算操作写入审计日志；
- 发布接口必须在服务端重新检查权限，不能依赖前端隐藏按钮。

## 规则模型

### 固定分组

系统始终包含七个分组：

| 分组 | 默认注释 |
| --- | --- |
| A | 注册后尚未进入支付流程 |
| B | 已进入支付流程但尚未完成首单 |
| C | 已完成首单但尚未产生成功调用 |
| D | 曾成功调用、有余额但已长期未调用 |
| E | 余额不足或耗尽、等待复充 |
| F | 存在服务异常，需要紧急人工介入 |
| G | 未命中召回条件的健康或其他用户 |

字母是系统标识，历史数据、任务、模板和报表继续使用该标识。注释是管理员可编辑文本，长度为 1–500 个字符，不参与条件计算。

### 条件结构

每个分组包含一个或多个“或者分支”，每个分支包含一个或多个“并且条件”：

```text
分组命中 =
  （条件 1 并且 条件 2）
  或者
  （条件 3 并且 条件 4）
```

条件由三个部分组成：

1. 字段；
2. 与字段类型匹配的运算符；
3. 一个或多个比较值。

系统只保存结构化 JSON，不接受自由文本表达式、脚本、SQL、正则表达式或任意数据库字段。

### 互斥顺序

系统使用“从上到下，首次命中即停止”的方式分配用户：

1. F 固定为第一优先级；
2. A–E 允许管理员拖动调整顺序；
3. G 固定为最后的无条件兜底组；
4. 用户命中第一个分组后不再继续判断后续分组。

因此，每个用户始终只属于一个组。规则预览仍会计算用户在不考虑优先级时可能命中的全部分组，用于暴露规则重叠。

F 必须至少包含一个有效条件分支。G 不允许配置条件，含义固定为“前面所有分组均未命中”。

## 可选字段白名单

首版字段来自当前 RightToken 用户资料和已定义的正式接入字段。

| 类别 | 字段 | 类型与说明 |
| --- | --- | --- |
| 注册 | 注册时间 | 绝对时间 |
| 注册 | 注册后经过时间 | 相对当前时间计算的时长 |
| 注册 | 注册来源 | 文本枚举或值列表 |
| 地区 | 注册 IP | 敏感文本；仅支持精确匹配、属于列表、不属于列表 |
| 地区 | 国家 | ISO 国家代码 |
| 地区 | 地区 | 已标准化地区文本 |
| 地区 | 语言 | 已标准化语言代码 |
| 地区 | 时区 | IANA 时区 |
| 支付 | 是否进入支付 | 根据支付流程开始时间计算 |
| 支付 | 支付状态 | 未发起、处理中、成功、失败、取消、过期 |
| 支付 | 首次支付时间 | 可判断为空、非空或相对时长 |
| 支付 | 累计支付金额 | 最小货币单位整数 |
| 调用 | 成功调用次数 | 非负整数 |
| 调用 | 首次调用时间 | 可判断为空、非空或相对时长 |
| 调用 | 最后调用时间 | 可判断为空、非空或相对时长 |
| 调用 | 距离最后调用时间 | 相对当前时间计算的时长 |
| 余额 | 当前余额 | 最小货币单位整数 |
| 余额 | 余额最后变化时间 | 可判断为空、非空或相对时长 |
| 余额 | 余额耗尽时长 | 当前余额达到指定阈值后的持续时长 |
| 异常 | 是否存在服务异常 | 布尔值 |
| 异常 | 异常发生时间 | 可判断为空、非空或相对时长 |
| 用户状态 | 是否退订 | 布尔值 |
| 用户状态 | 是否暂停 | 布尔值 |
| 基础信息 | 用户 ID | 精确匹配或值列表 |
| 基础信息 | 邮箱域名 | 精确匹配、属于列表、不属于列表 |

“当前分组、负责人、任务状态、规则版本”不能作为分组条件，避免循环判断和用户反复跳组。

注册 IP 在数据库中继续加密保存。规则预览和执行只在服务端受控解密；响应、审计元数据和错误信息不得暴露批量明文 IP。

## 运算符

编辑器根据字段类型限制可选运算符：

- 布尔值：是、否；
- 枚举：等于、不等于、属于、不属于；
- 数字和金额：等于、不等于、大于、大于等于、小于、小于等于、区间；
- 绝对时间：早于、早于或等于、晚于、晚于或等于、为空、非空；
- 相对时长：超过、不足、介于；单位为分钟、小时或天；
- 文本标识：等于、不等于、属于列表、不属于列表；
- IP：等于、不等于、属于列表、不属于列表。

字段、运算符和值必须经过同一份服务端注册表校验。前端使用该注册表的安全展示数据生成控件，不能自行决定运算符。

## 任务策略

分组条件与运营任务策略分开显示，避免把“进入分组”和“多久提醒”混为一谈。

每个 A–E 分组可以配置：

- 是否创建个人召回任务；
- 命中分组后等待多久创建任务；
- 任务等级：普通、重要、紧急；
- 任务创建后的处理时限；
- 默认邮件模板标识。

F 固定为立即创建紧急任务，管理员只能在安全范围内调整处理时限和模板。G 固定不创建个人召回任务。

退订和暂停用户仍可被正确分组，但任务和邮件服务继续执行现有退订、暂停和频率拦截，分组规则不能绕过这些保护。

## 页面交互

### 页面顶部

顶部显示：

- 当前生效版本；
- 最近发布时间和发布人；
- 当前规则状态；
- 最近一次全量重算进度；
- “查看历史版本”和“预览并发布”入口。

页面明确解释整个互斥算法：

> 系统从上到下判断。用户命中第一个分组后停止，因此每个用户只进入一个组。F 始终优先，G 接收所有未命中的用户。

### 分组列表

页面按 F、管理员排序后的 A–E、G 展示。每个分组是可展开的规则区，不使用只有数字而没有语义的参数表。

每个分组区显示：

- 固定字母；
- 可编辑注释；
- 自然语言规则摘要；
- 条件分支；
- 任务策略；
- 当前命中用户数量。

管理员可以：

- 添加或删除“或者分支”；
- 在分支内添加或删除“并且条件”；
- 选择字段、运算符和值；
- 复制一个条件分支；
- 拖动 A–E 调整顺序；
- 使用键盘“上移、下移”完成同样排序；
- 恢复该组的系统默认条件。

F 和 G 显示锁定原因。G 只显示兜底说明，不显示条件编辑器。

### 自然语言解释

系统实时把结构化条件转换成中文，例如：

> 如果成功调用次数大于 0，并且当前余额大于 0，并且距离最后调用时间超过 7 天，则进入 D 组。

自然语言只用于解释，实际执行始终使用结构化规则，避免文案与执行逻辑分离。

未保存修改显示“草稿未发布”。离开页面前如存在修改，浏览器提示管理员保留编辑或放弃修改。

## 预览与发布

### 预览

管理员点击“预览并发布”后，服务端对数据库中的全部用户执行只读影子计算，不修改用户、任务或当前生效版本。

预览显示：

- 新规则下 A–G 的预计人数；
- 每组新增、移出和保持人数；
- 预计发生分组迁移的总人数；
- 同时满足多个非兜底组的用户数量及抽样；
- 未命中 F/A–E、最终由 G 接收的用户数量；
- 预计取消的未开始自动任务数量；
- 预计创建的新任务数量；
- 预计立即产生的 F 组紧急任务数量；
- 输入校验错误和阻止发布的安全问题。

规则重叠是提示信息，不必然阻止发布，因为优先级可以有意解决重叠。以下问题阻止发布：

- F 没有条件；
- A–E 中启用的分组没有有效条件；
- 使用了未知字段或不兼容运算符；
- 条件值缺失或超出安全范围；
- 顺序缺少、重复或包含 F/G；
- 预览所依据的草稿与提交发布的草稿哈希不一致。

### 确认发布

发布确认页显示版本变化、预计迁移和任务影响。管理员填写简短变更说明后点击“确认发布新版本”。

发布过程：

1. 再次校验权限、草稿和预览哈希；
2. 创建不可变的新规则版本；
3. 将新版本设为当前生效版本；
4. 创建全量重算运行记录；
5. 后台分批重新计算全部用户；
6. 页面轮询并显示处理进度、成功数量、失败数量和最终结果。

发布按钮必须防重复提交。同一个预览哈希和发布请求使用幂等键，网络重试不能创建两个版本。

## 全量重新计算

新版本发布后，所有新事件立即使用新版本。现有用户由后台任务分批处理：

- 每批重新读取用户最新事实，避免使用预览时的旧快照；
- 根据新规则计算唯一分组；
- 只有分组或规则版本发生变化时才更新用户；
- 分组变化写入 `SegmentHistory`，包含原组、新组、规则版本和命中原因；
- 没有换组的用户也更新 `segmentRuleVersion`；
- 单个用户失败不终止整次运行，失败记录稳定错误码并可重试；
- 重试是幂等的，不重复创建迁移记录或任务；
- 用户在重算过程中发生新事件时，以较新的用户事实和新规则版本为准。

运行状态至少包含：等待、运行中、已完成、部分失败、失败。部分失败可以从失败用户继续重试。

## 任务迁移

重新分组后同步处理任务：

- `UNASSIGNED` 和 `TODO` 状态的旧自动任务，如已不符合新分组，则自动取消；
- 取消原因记录为“分组规则变更”，并保留原任务历史；
- `IN_PROGRESS`、`WAITING_USER`、人工创建和邮件回复产生的任务不自动取消；
- 新分组任务策略需要任务时，按新规则版本创建任务；
- 进入 F 组时立即创建紧急任务并触发既有通知流程；
- 进入 G 组时不创建个人召回任务；
- 任务的取消、保留和新建全部写入任务活动及审计日志。

旧任务不改写为新分组任务，避免丢失原始触发原因。新任务使用新的规则版本和独立触发键。

## 历史版本与回滚

规则版本不可修改、不可删除。历史页显示：

- 版本号、发布人、发布时间和变更说明；
- A–G 注释、条件顺序和任务策略；
- 当次预览摘要；
- 当次全量重算结果；
- 与当前版本的差异。

“回滚”不是重新激活旧数据库记录，而是复制旧版本配置并发布为一个新的版本。回滚同样需要预览、确认和全量重新计算，确保审计链连续。

## 数据结构

继续使用 `AutomationRuleVersion` 保存不可变配置，`kind` 保持为 `segmentation`。新配置包含：

```text
schemaVersion
groups[]
  code
  annotation
  enabled
  order
  branches[]
    clauses[]
      field
      operator
      value
  taskPolicy
changeSummary
```

新增全量重算运行记录，保存：

- 规则版本；
- 状态；
- 用户总数、已处理数、成功数、失败数；
- 分组迁移数；
- 取消任务数、新建任务数；
- 开始和完成时间；
- 稳定错误摘要。

预览结果使用短期有效的服务端记录或签名令牌保存草稿哈希和汇总数据，不在客户端提交任意“预计影响数”作为可信结果。

旧版只有时间和余额参数的配置在读取时转换为等价的完整默认规则集。只有管理员主动发布时才写入新结构，部署升级本身不触发全量重算。

## 接口边界

接口按职责分离：

- 获取当前规则和字段注册表；
- 校验草稿；
- 预览规则影响；
- 发布经过预览的规则；
- 查询重算进度；
- 查询历史版本和版本差异；
- 预览并执行回滚。

所有写接口执行同源校验、会话校验、权限校验、结构校验和审计。接口不接受客户端提供的任意字段名、表达式或计算结果。

## 错误处理

- 无效条件返回具体到分组、分支和条件的错误位置；
- 预览期间用户事实变化不阻止发布，正式重算会重新读取最新事实；
- 发布后后台运行失败时，已发布版本保持生效，页面显示部分失败并允许重试；
- 不能因为个别用户数据异常回退整个规则版本；
- 若配置本身无法编译，必须在发布事务前拒绝；
- 任何错误响应不得包含邮箱、明文 IP、凭据或完整用户快照。

## 测试标准

### 单元测试

- 每种字段类型只允许匹配的运算符；
- 条件组正确执行“组内并且、组间或者”；
- F 始终优先，G 始终兜底；
- A–E 顺序变化会改变重叠用户的最终分组；
- 自然语言解释与结构化条件一致；
- 旧配置可以转换为等价的新规则集；
- 任务策略的 F/G 安全限制不能被绕过。

### 组件测试

- 管理员可以编辑注释、增删条件和条件组；
- 只能选择白名单字段；
- 字段变化后运算符和值控件同步变化；
- A–E 支持鼠标和键盘排序；
- F/G 锁定状态清晰；
- 草稿、校验错误、预览结果和发布进度正确显示；
- 运营只能查看，不能看到可执行的发布控件。

### 集成测试

- 无权限成员不能预览、发布或回滚；
- 预览不修改用户和任务；
- 发布生成唯一活动版本和唯一重算运行；
- 全量重算为每个用户分配且仅分配一个组；
- 分组迁移、任务取消、新任务和审计记录正确；
- 并发发布和重复提交不会创建重复版本；
- 部分失败可以幂等重试；
- 回滚创建新版本并再次全量重算。

### 端到端测试

- 管理员完成“编辑 → 校验 → 预览 → 确认 → 查看重算结果”；
- 管理员调整 D/E 顺序后，重叠用户进入优先组；
- 发布后新用户和存量用户都使用新版本；
- F 用户产生紧急任务，G 用户不产生个人任务；
- 历史版本可查看差异并完成安全回滚。

## 非目标

- 不新增 H 或其他分组；
- 不允许重命名 A–G；
- 不允许执行任意代码、SQL、正则表达式或自定义数据库字段；
- 不把负责人、任务状态或当前分组作为条件；
- 不允许分组规则绕过退订、暂停、权限或频率限制；
- 不在本次范围内改变 RightToken 正式用户接口之外的数据来源；
- 不在部署升级时自动发布新规则或触发全量重算。
