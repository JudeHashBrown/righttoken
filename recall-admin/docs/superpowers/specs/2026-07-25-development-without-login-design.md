# RightToken 召回后台本地免登录设计

## 目标

本地开发期间不出现登录、密码、验证码、二次验证、退出或会话过期流程。访问后台任意页面时直接进入系统，并以数据库中的主管理员作为当前操作人。正式接入 RightToken 主站后，由主站身份适配器替换本地自动身份。

## 方案选择

采用“身份提供者边界 + 本地自动主管理员”方案。

- 不采用伪造浏览器 Cookie：它仍然依赖会话和安全校验，服务重启后容易再次失效。
- 不把所有权限判断删除：任务、审计、发布记录和负责人关系仍然需要一个真实成员 ID。
- 本地环境由服务端直接解析主管理员，页面和接口共用同一身份来源。
- 正式环境只允许未来的 `righttoken` 身份模式，不恢复独立邮箱密码登录。

## 页面行为

- `/`、`/login` 和 `/2fa/setup` 都直接转到 `/dashboard`。
- 所有后台路由不再检查 Cookie 或二次验证状态。
- 顶部不显示“退出”操作。
- 成员页面不展示二次验证和有效会话数据。
- 邀请成员不再要求当前账号密码或二次验证码。

## 接口行为

- 本地开发请求不需要会话 Cookie。
- 本地开发写接口不执行登录同源校验。
- 权限仍按自动主管理员角色执行，业务层继续记录真实 `Member.id`。
- 需要“最近重新验证”的管理操作在本地开发模式直接放行。
- RightToken 内部事件接口的密钥校验不属于后台登录，保持不变。

## 数据和未来接入

- 不删除 `Member`、角色和审计关系，它们属于业务权限与责任归属。
- 旧的 `Session`、密码和二次验证数据库字段暂不做破坏性迁移，避免阻塞本地开发和未来数据迁移。
- 登录页面与活跃登录接口从应用路由中移除。
- 后续主站接入只需实现 `righttoken` 身份解析，并返回与本地开发身份相同的成员上下文。

## 错误处理

- 如果数据库中没有启用的主管理员，页面和接口返回明确的开发环境配置错误，而不是跳回登录页。
- 正式环境不得自动降级到本地免登录身份。

## 验收标准

1. 清空浏览器 Cookie 后可直接打开 `/dashboard`、`/tasks` 和 `/automation/segments`。
2. `/login` 不再展示登录表单。
3. 写接口在没有会话 Cookie 时仍可由本地主管理员完成操作。
4. 页面没有登录、退出、二次验证和重新验证入口。
5. 现有角色权限、审计、任务与规则发布功能不受影响。
