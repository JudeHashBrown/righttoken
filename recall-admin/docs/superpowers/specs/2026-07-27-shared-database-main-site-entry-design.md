# RightToken 用户运营管理共库集成设计

## 1. 目标

将现有用户召回管理功能作为 RightToken 主站后台的受控子功能提供：

- 在主站侧边栏“个人资料”下方显示“用户运营管理”入口。
- 只有获得召回权限的主站账号可以看到并进入。
- 用户点击后自动进入，不再输入独立账号、密码或验证码。
- 主站与运营后台共用同一个 PostgreSQL 数据库。
- 注册、支付、余额、调用和注册 IP 等用户事实直接读取主站数据，不再复制到独立召回数据库。
- 保留召回业务自身的分组、任务、负责人、邮件、通知、规则和审计数据。

## 2. 不变的产品边界

- 运营后台继续使用现有 Next.js 页面和 Worker，不重写为 Vue 页面。
- 生产访问地址继续使用 `https://recall.righttoken.ai`，但入口只从主站受控菜单进入。
- 主站已有登录状态继续作为唯一身份来源。
- 召回后台不提供生产环境免登录模式。
- 主管理员、管理员、运营三种角色保持不变。
- 只有主管理员可以导出 CSV、管理管理员、转移主管理员和发布全局规则。
- 管理员可以查看全局数据；运营只能处理分配给自己的用户和任务。

## 3. 推荐架构

### 3.1 一个数据库，两个数据边界

使用 RightToken 现有 PostgreSQL 数据库，不再部署 `recall-db`。

- `public`：RightToken 主站现有表，由 Go 后端及其迁移管理。
- `recall`：运营后台专属表，由召回应用的 Prisma 迁移管理。

两个应用连接同一个数据库，但数据库账号权限不同：

- RightToken 主站账号继续管理 `public`。
- 召回 Web 和 Worker 对所需 `public` 表只有 `SELECT` 权限。
- 召回 Web 和 Worker 只对 `recall` 命名空间拥有读写权限。
- 召回 Prisma 迁移不得创建、修改或删除 `public` 中的任何主站表。

这属于共用主库，不是数据库副本。独立命名空间用于避免表名冲突、误迁移和误删除。

### 3.2 用户事实直接读取

以下字段始终以主站表为准，运营后台不再保存第二份业务事实：

- 主站用户 ID、邮箱、用户名和注册时间。
- 注册 IP。
- 是否进入支付流程、首单支付时间和累计支付金额。
- 当前余额和币种。
- 首次成功调用、最后成功调用和成功调用次数。
- 主站服务异常状态。

召回服务增加 `RightTokenUserFactsRepository`，通过只读 SQL 从 `public` 表查询并组装统一的用户事实对象。页面列表、用户详情、A–G 分组计算、地区识别和任务触发都使用该对象。

现有 `GET /api/v1/admin/recall/users`、定时增量同步和每日全量校准在共库模式下不再参与生产数据链路。切换验证完成后删除相关密钥和调度配置。

### 3.3 只保存运营状态

`recall` 中保留的用户关联记录只保存召回系统产生的状态，并通过主站用户 ID 关联主站用户：

- 当前 A–G 分组和规则版本。
- 运营负责人及分配原因。
- 地区判断结果、判断来源和人工修正。
- 暂停、退订和人工覆盖状态。
- 最近一次分组、地区及任务计算时间。

邮箱、注册 IP、余额、支付金额和调用次数不再作为召回用户表的持久化副本。

任务、邮件、备注、事件、通知和审计日志继续保存在 `recall` 中。这些是运营系统产生的新业务数据，不属于主站用户数据副本。

## 4. 主站入口与身份流程

### 4.1 菜单位置

“用户运营管理”位于主站用户侧边栏“个人资料”下方，即需求截图红框位置。

主站管理员视图也显示同一入口，但仍以召回成员权限为准；主站管理员身份本身不自动获得召回权限。

### 4.2 显示条件

主站登录后调用现有权限检查：

`GET /api/v1/user/recall/access`

- 返回 `allowed=true`：显示入口。
- 返回 `allowed=false`、未授权或检查失败：不显示入口。

后端在真正进入时再次校验权限，不能只依赖前端隐藏菜单。

### 4.3 自动进入

点击入口后：

1. 主站后端重新校验召回权限。
2. 主站签发 60 秒有效、只能使用一次的登录票据。
3. 浏览器跳转到召回后台票据兑换地址。
4. 召回后台建立 HttpOnly 安全会话。
5. 用户直接进入运营仪表盘。

这一过程对用户表现为点击一个菜单后直接进入，不出现第二套登录页面。

保留短期票据是因为主站和 `recall.righttoken.ai` 属于不同应用，不能把主站浏览器令牌直接交给召回后台。

## 5. 成员与权限

`recall.Member` 必须绑定稳定的 RightToken 主站用户 ID。

- 主管理员可以为已注册的主站用户授予管理员或运营权限。
- 管理员只能授予和撤销运营权限。
- 运营不能管理成员。
- 撤销权限后立即终止该成员的全部召回会话。
- 主管理员不能删除自己；必须先转移主管理员身份。
- 停用成员后，主站菜单在下一次权限检查时消失，直接进入接口也返回拒绝。

用户邮箱只用于搜索和展示，不作为长期身份主键。主站用户 ID 才是成员绑定依据。

## 6. 数据计算与实时性

共库后不再等待 15 分钟同步：

- 用户列表和详情读取当前主站事实。
- 分组规则发布后直接扫描主站有效用户并全量重算。
- 定时任务只负责分组复核、任务到期、邮件收取和通知重试，不负责复制用户数据。
- 支付、余额和调用变化可以通过现有 Worker 周期检查，后续再增加主站事件通知以获得秒级触发。

首版保留短周期事实复核任务，默认每 5 分钟查找发生变化的主站用户；它只重新计算召回状态，不复制用户事实。

## 7. 数据库迁移

切换必须分阶段执行：

1. 在主站数据库创建 `recall` 命名空间。
2. 将现有召回业务表迁移到 `recall`，不触碰 `public`。
3. 创建最小化的召回用户状态表，以主站用户 ID 为唯一键。
4. 从现有 `UserProfile.externalUserId` 回填主站用户 ID 和运营状态。
5. 对照现有同步结果与共库实时查询结果，核对用户数、分组和任务。
6. 将页面和 Worker 切换到共库事实仓储。
7. 停止增量同步和全量校准。
8. 确认稳定后删除召回用户事实副本字段和独立数据库容器配置。

迁移脚本必须支持只读预检、事务回滚和重复执行。任何主站用户 ID 无法匹配的召回记录进入迁移报告，不得静默丢弃。

## 8. 部署调整

- 删除生产 Compose 中的 `recall-db` 服务和独立数据库卷。
- `recall-web`、`recall-worker` 和 `recall-migrate` 使用主站数据库地址。
- 使用独立数据库账号，例如 `righttoken_recall_app`。
- 该账号只拥有所需主站表的 `SELECT` 权限和 `recall` 命名空间的读写权限。
- 保留 `recall.righttoken.ai` 的反向代理、健康检查和独立进程。
- 移除 `RECALL_EXPORT_SECRET`、`RECALL_RIGHTTOKEN_API_TOKEN` 和用户同步相关生产变量。
- 保留 SSO 签名密钥、内部授权检查密钥、邮件、企微和加密密钥。

## 9. 安全要求

- 前端不得获得数据库地址、数据库密码或内部密钥。
- 所有权限必须由服务端二次校验。
- 共库连接必须启用 TLS，并限制来源网络。
- 召回数据库账号不得拥有主站表的 `INSERT`、`UPDATE`、`DELETE`、`TRUNCATE` 或 `ALTER` 权限。
- CSV 导出继续执行主管理员权限检查并记录审计日志。
- 邮箱和 IP 只在有权限的后台页面按业务需要展示，不写入日志或错误信息。
- 生产环境检测到免登录开发模式时必须拒绝启动。

## 10. 测试

### 主站前端

- 未授权用户看不到“用户运营管理”。
- 授权用户在“个人资料”下方看到入口。
- 点击入口后调用 SSO 并跳转。
- 权限接口失败时入口保持隐藏。

### 主站后端

- 未登录、未授权、已停用成员无法取得 SSO 地址。
- 一次性票据过期或重复使用时被拒绝。
- 主站管理员但非召回成员时仍被拒绝。

### 共库数据

- 召回账号可以读取规定的主站表，但不能修改。
- 召回迁移不能修改 `public` 表结构。
- 注册、支付、余额、成功调用和 IP 查询与主站结果一致。
- 金额单位和成功调用过滤准确。
- 分组发布可以覆盖全部有效用户且每人只进入一个组。

### 权限

- 只有主管理员可以导出 CSV、管理管理员和转移主管理员。
- 管理员可以管理运营成员但不能管理主管理员。
- 运营只能查看和处理分配给自己的用户与任务。
- 权限撤销后现有会话立即失效。

## 11. 验收标准

- 有权限用户从主站菜单一次点击进入运营后台。
- 无权限用户看不到入口，也无法通过直接地址进入。
- 生产环境只有一个 PostgreSQL 数据库实例，不再运行独立 `recall-db`。
- 运营后台直接读取主站用户事实，不再执行用户导出与同步。
- 主站表没有被召回 Prisma 迁移修改。
- A–G 分组、地区分配、任务、邮件、通知、成员权限和审计功能保持可用。
- 用户事实变化后最迟 5 分钟完成召回状态重算；规则发布后可以全量重算所有有效用户。
