# 列表表头筛选与最新优先排序设计

## 目标

用户列表的“地区、负责人”以及任务列表的“分组、负责人”改为表头下拉筛选。
用户、任务及问题/异常类列表默认按业务发生时间从近到远展示。

## 交互

- 筛选控件直接显示在对应表头中，保留列名并提供“全部…”选项。
- 选择下拉项后自动提交当前页面的 GET 查询。
- 搜索、标签页和其他已有条件继续保留；分页链接继续携带筛选参数。
- 运营人员只能查看自己的用户和任务，因此不显示可选择其他负责人的下拉框。
- 页面上方不再重复显示地区、负责人或分组筛选。

## 数据与排序

- 复用现有 `region`、`ownerId`、`segment`、`assigneeId` URL 参数和服务端查询，
  不增加客户端筛选状态。
- 用户列表以 `lastExternalEventAt` 倒序为主；没有外部事件时以注册时间倒序；
  最后使用 `id` 倒序保证稳定。
- 任务列表以 `createdAt` 倒序，再以 `id` 倒序。
- 用户详情中的事件、分组历史、备注、任务活动继续使用各自发生时间倒序。
- 仪表盘“优先任务”仍保留优先级与截止时间语义，因为它是行动优先队列，
  不是普通时间列表。

## 组件

新增一个轻量表头筛选组件，接收标签、参数名、当前值和选项，使用 GET 表单
自动提交。`UserTable` 和 `TaskTable` 接收筛选配置并在指定表头渲染该组件。

## 验收

- 四个红框列均可通过下拉菜单筛选。
- 选择条件后 URL 参数正确，其他条件不丢失。
- 用户和任务查询均返回最新记录在前。
- 空列表、分页、权限范围和现有筛选不受影响。
- 单元、集成、类型、规范和生产构建验证通过。
