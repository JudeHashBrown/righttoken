# RightToken 用户人工确认运营地区设计

## 1. 目标

地区判定和负责人分配是两个独立决策：

- 地区判定回答“该用户属于哪里”。
- 负责人分配回答“该地区由谁负责”。

当邮箱、注册 IP 和主站注册信息不足以判断用户所属地区时，管理员不应只能人工指定负责人。系统需要同时保留两项独立能力：

- 人工确认用户的运营地区。
- 人工调整用户负责人。

人工确认的地区具有最高优先级，只有管理员明确执行“恢复自动判定地区”后，系统才可以再次使用自动来源更新地区。

## 2. 状态模型

新增 `LocationAssignmentMode`：

- `AUTO`：地区由邮箱、注册 IP 或主站注册信息自动判定。
- `MANUAL`：地区由管理员人工确认。

在 `UserProfile` 增加：

- `locationAssignmentMode`：地区判定模式，默认 `AUTO`。
- `locationAssignedAt`：最近一次人工确认或恢复自动判定的时间。
- `locationAssignedById`：执行人工确认的管理员。
- `locationAssignmentReason`：人工确认原因。

现有 `countryCode` 和 `region` 继续作为当前生效的运营地区，不增加第二套地区字段。原始 IP 地区继续保存在 `ipCountryCode` 和 `ipRegion`，用于展示和恢复自动判定。

地区判定状态与现有负责人分配状态彼此独立：

- 地区可以是人工确认，负责人仍由系统分配。
- 地区可以是自动判定，负责人由管理员人工指定。
- 两者也可以同时人工锁定。

## 3. 人工确认地区

主管理员和管理员可以在用户详情的“运营归属”区域点击“确认所属地区”。

表单包含：

- 国家或地区，必填，使用系统支持的标准国家或地区选项。
- 省 / 州 / 地区，可选自由文本，去除首尾空格，最长 120 个字符。
- 确认原因，必填，最长 500 个字符。

提交后在同一个数据库事务中：

1. 锁定用户记录，避免与同步任务并发覆盖。
2. 校验操作者为有效的主管理员或管理员。
3. 保存标准化后的国家代码和地区文本。
4. 将地区判定模式更新为 `MANUAL`。
5. 保存确认人、确认原因和时间。
6. 如果负责人当前为 `AUTO`，立即按新地区运行现有负责人分配规则。
7. 如果负责人发生变化，同步转移全部未完成任务；已完成和已取消任务不变。
8. 写入审计记录。

如果负责人当前为 `MANUAL`，人工确认地区不得覆盖负责人，也不得转移任务。

## 4. 恢复自动判定

人工确认地区的用户显示“恢复自动判定”操作。

确认后在同一个数据库事务中：

1. 使用当前保存的邮箱、注册 IP、原始 IP 地区和最新生效的邮箱来源规则重新计算地区。
2. 将地区判定模式更新为 `AUTO`。
3. 清空人工确认人和人工原因，记录恢复时间。
4. 如果负责人当前为 `AUTO`，立即按恢复后的地区重新运行负责人分配规则并转移未完成任务。
5. 如果负责人当前为 `MANUAL`，保持负责人和任务不变。
6. 写入审计记录。

恢复自动判定不等于清空地区。即使来源仍然不足，也要保存一次完整的自动判定结果，并在页面显示“未识别 · 注册来源信息不足”。

## 5. 自动同步与批量重算

用户事件同步、地区规则预览、地区批量重算和注册信息补全必须遵守地区锁定：

- `AUTO` 用户继续正常更新地区。
- `MANUAL` 用户跳过自动地区写入。
- 跳过不能算作批处理失败。
- 地区规则预览可以展示人工地区用户，但必须标记“人工确认，不会被发布结果覆盖”。

人工确认地区后，系统仍可以更新原始 IP 地区和其他事实数据；只是不允许这些来源改写当前生效的 `countryCode` 和 `region`。

## 6. 页面设计

### 6.1 用户详情

“运营归属”区域显示：

- 当前国家和省 / 州 / 地区。
- `系统判定` 或 `人工确认`状态。
- 判定依据或人工确认原因。
- 人工确认时显示确认人和确认时间。

管理员操作：

- 始终提供“确认所属地区”，用于补全未知地区或修正错误地区。
- 人工确认状态额外提供“恢复自动判定”。
- 原有“调整负责人”和“恢复自动分配”保持不变，继续位于负责人区域。

采用现有页面的行内渐进式编辑方式，不新增弹窗。国家、地区和原因字段使用现有表单控件与按钮样式。

### 6.2 用户列表

运营归属列增加简短状态：

- 自动来源显示现有判定结果。
- 人工确认显示“人工确认”标签。
- 未识别仍显示“未识别 · 注册来源信息不足”。

列表不展开编辑表单，点击用户进入详情后操作，避免表格内同时出现地区和负责人两个复杂编辑器。

## 7. 接口

新增用户地区接口：

- `PATCH /api/users/:id/location`
  - 请求：`countryCode`、可选 `region`、`reason`。
  - 作用：人工确认地区，并在负责人为自动模式时重新分配。
- `DELETE /api/users/:id/location`
  - 作用：恢复自动判定，并在负责人为自动模式时重新分配。

接口复用 `operators:manage` 权限和同源请求校验。普通运营人员只能查看，不能调用。

响应包含：

- 变更前后地区。
- 地区判定模式。
- 负责人是否重新计算。
- 变更前后负责人。
- 转移的未完成任务数。

## 8. 审计

新增审计动作：

- `user.location_manually_assigned`
- `user.location_auto_restored`

审计元数据包括：

- 变更前后国家和地区。
- 地区判定模式。
- 操作原因。
- 原负责人和新负责人。
- 是否跳过负责人重算及原因。
- 转移的未完成任务数量。

## 9. 错误处理

页面只显示可行动的中文提示：

- 国家或地区未选择：表单内阻止提交。
- 原因未填写：表单内阻止提交。
- 用户已删除：提示用户不存在或已停用。
- 权限不足：接口返回 403，页面不向普通运营人员展示入口。
- 保存冲突或服务异常：保留表单内容并提示“所属地区没有更新，请稍后重试”。
- 恢复失败：提示“暂时无法恢复自动判定，请刷新后重试”。

## 10. 测试与验收

必须覆盖：

1. 人工确认地区会写入模式、地区、确认人、原因和时间。
2. 人工地区不会被事件同步和批量地区重算覆盖。
3. 人工确认地区时，自动负责人按新地区重算并转移未完成任务。
4. 人工确认地区时，人工负责人保持不变。
5. 恢复自动判定会使用最新来源重新计算地区。
6. 恢复自动判定时，仅自动负责人重新分配。
7. 普通运营人员无法修改或恢复地区。
8. 页面同时存在“确认所属地区”和“调整负责人”，且状态与按钮互不混淆。
9. 表单键盘可操作，标签与错误提示可被辅助技术识别。

## 11. 非目标

- 不建立独立的人工地区历史表；完整历史由审计日志保存。
- 不允许普通运营人员修改地区。
- 不改变现有地区分配规则的匹配优先级。
- 不根据人工选择的负责人反推地区。
- 不在本次改动中引入地图、地址搜索或新的外部地理服务。
