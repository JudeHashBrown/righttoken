# HTML 邮件源码编辑与预览设计

> 状态：已完成方案与界面确认，待书面规格确认  
> 日期：2026-07-31

## 1. 目标

在现有邮件富文本、图片、附件、模板、单发、群发和回复能力之上，增加完整 HTML 邮件源码编辑能力。运营人员可以在“可视化编辑”“HTML 源码”“发送预览”之间切换，发送前看到安全清洗后的实际内容。

该能力必须同时满足：

- 保留现有可视化富文本编辑体验。
- 支持粘贴或编辑完整 HTML 邮件文档。
- 支持 `DOCTYPE`、`html`、`head`、`style`、表格布局、内联 CSS 和媒体查询。
- 支持系统上传的内嵌图片与 HTTPS 外链图片。
- 阻止脚本、表单、iframe、事件属性和危险 URL 等主动内容。
- 为每封 HTML 邮件生成纯文本备用版本。
- 单封邮件、群发批次、模板和邮件回复使用相同的 HTML 处理规则。

## 2. 已确认的编辑体验

邮件正文区域顶部提供三个模式：

1. **可视化编辑**：沿用当前工具栏和所见即所得编辑器。
2. **HTML 源码**：编辑完整 HTML 文档，显示基础语法错误和安全清洗提示。
3. **发送预览**：在隔离区域中展示安全清洗、图片解析和变量替换后的最终效果。

右侧固定显示“发送检查”：

- HTML 是否通过安全检查。
- 是否已生成纯文本版本。
- 是否存在 HTTPS 外链图片。
- 是否存在未替换变量。
- 是否存在失效的系统图片。
- 是否存在邮件客户端兼容性风险。

发送按钮继续沿用现有人工审核、权限、退订、暂停联系、频率控制和发件箱可用性校验。

## 3. 编辑模式与内容所有权

### 3.1 单一规范内容

编辑器只维护一份规范化 HTML，不为可视化模式和源码模式保存两份相互独立的正文。`bodyHtml` 是 HTML 邮件的权威内容，`bodyText` 是从当前 HTML 自动生成、可供发送和检索使用的纯文本版本。

可视化编辑器修改正文后更新 `bodyHtml` 和 `bodyText`。源码编辑器修改后，先在本地解析并显示诊断；通过最低结构校验后更新共享内容。

### 3.2 模式切换

- 可视化编辑切到源码编辑：无损显示当前完整 HTML。
- 源码编辑切到发送预览：服务端执行与发送完全相同的安全清洗和资源解析，再返回预览。
- 源码编辑切回可视化编辑：如果内容只使用可视化编辑器可表达的结构，则直接切换。
- 如果 HTML 包含复杂表格、`head`、`style`、媒体查询或可视化编辑器无法无损表达的结构，页面必须提示“切换会简化布局”。只有用户明确确认后才能转换。
- 取消确认时保留源码内容，不发生静默改写。

### 3.3 导入

HTML 源码模式支持：

- 直接粘贴 HTML。
- 从本地选择 `.html` 或 `.htm` 文件导入。

导入只读取文本，不加载本地关联资源。导入后立即显示语法与安全诊断，但不会自动发送或发布模板。

## 4. HTML 安全模型

### 4.1 允许内容

允许邮件客户端常用的静态结构，包括：

- 文档结构：`html`、`head`、`body`、`title`、`meta`、`style`。
- 内容结构：标题、段落、换行、分隔线、列表、引用、容器。
- 邮件布局：`table`、`thead`、`tbody`、`tfoot`、`tr`、`th`、`td`。
- 文本样式：`strong`、`b`、`em`、`i`、`u`、`s`、`span`。
- 链接与图片：`a`、`img`。
- 常见邮件属性、无障碍属性、尺寸、对齐和安全的 `class`。
- 邮件常用内联 CSS，以及 `<style>` 中的静态选择器和 `@media` 查询。

### 4.2 禁止内容

无条件移除：

- `script`、`iframe`、`frame`、`frameset`、`object`、`embed`。
- `form`、`input`、`button`、`select`、`textarea`。
- `video`、`audio`、可执行 SVG 和其他主动内容。
- 所有 `on*` 事件属性。
- `javascript:`、`vbscript:`、非图片用途的 `data:` URL。
- CSS `expression()`、脚本 URL、外部样式导入和其他可执行 CSS。
- 可突破预览隔离或覆盖管理后台界面的内容。

安全清洗必须在服务端执行。浏览器端诊断仅用于快速反馈，不能代替发送前的服务端清洗。

### 4.3 完整文档保存

数据库继续使用现有 `bodyHtml` 字段，不新增第二套 HTML 字段。服务端保存经过清洗的规范化完整文档；发送、预览、模板发布和批次快照均使用同一处理函数，避免“预览内容”和“实际发送内容”不一致。

## 5. 图片与资源

### 5.1 系统上传图片

沿用现有邮件资产模型。源码中通过受控资产标识引用已上传图片，发送时解析为 CID 内嵌附件。系统图片继续遵守：

- 每封最多 10 张。
- 总大小最多 20 MB。
- 图片必须存在且有权被当前邮件使用。
- 正文引用与邮件资产列表必须一致。

### 5.2 HTTPS 外链图片

允许 `https://` 图片地址直接进入最终邮件。预览和发送检查必须提示：

- 收件方客户端可能默认隐藏外链图片。
- 外链服务器不可用时图片将无法显示。
- 外链图片可能向图片服务器暴露打开请求。

禁止 `http://`、协议相对地址、本地地址、文件地址和私有网络地址。系统不主动下载或代理外链图片，避免发送阶段发生服务端请求伪造或被不可信资源拖慢。

## 6. 预览流程

新增邮件预览接口，接收当前主题、HTML、资产引用和可选的示例变量，返回：

- 清洗后的完整 HTML。
- 自动生成的纯文本。
- 安全清洗摘要。
- 外链图片数量。
- 被移除的标签、属性和危险 URL 分类统计。
- 未替换变量。
- 失效资产。
- 是否允许进入发送步骤。

预览页面通过带严格沙箱属性的 iframe 展示返回的 HTML。预览 iframe 不允许脚本、表单、顶层导航或访问管理后台 DOM。预览必须使用服务端返回内容，不能直接渲染用户输入的原始 HTML。

为避免频繁请求，源码停止输入一段短暂时间后再刷新预览；显式进入“发送预览”时立即请求最新结果。

## 7. 发送与模板数据流

### 7.1 单封与回复

1. 编辑器提交 `bodyHtml`、自动生成的 `bodyText` 和资产引用。
2. API 使用共享邮件 HTML 处理器重新清洗并解析资源。
3. 现有发送守卫执行权限、退订、暂停、频率和变量校验。
4. 保存清洗后的 `bodyHtml` 与最终 `bodyText`。
5. Nodemailer 同时发送 `html` 与 `text` MIME 部分。
6. 发送历史和会话详情显示保存后的 HTML。

### 7.2 群发

创建群发批次时清洗并冻结 HTML 快照。每位收件人发送前只执行变量替换和受众级校验，不重新读取可变模板。批次详情保留当时的 HTML 和纯文本，确保重试发送与原批次一致。

### 7.3 模板

模板创建和发布支持同样的三模式编辑器。模板版本保存清洗后的 HTML 与纯文本。选择模板写信时直接加载其 HTML，不再仅用 `bodyText` 重建简单段落，从而保留复杂布局。

## 8. 错误处理

- HTML 解析失败：保留用户源码并标出错误位置，不覆盖最近一次有效内容。
- 内容全部被清洗为空：禁止发送并提示检查被移除内容。
- 存在危险内容：预览中说明已移除的类别；清洗后仍安全且正文非空时允许继续。
- 系统图片失效或引用不一致：禁止发送。
- 外链图片：只告警，不阻止发送。
- 预览接口失败：保留编辑内容，禁止以过期预览直接发送。
- 可视化转换可能丢失结构：必须二次确认。
- 发送阶段仍重新处理 HTML，防止绕过浏览器校验。

## 9. 兼容性边界

系统保证生成安全、符合 MIME 规范的 HTML 邮件，但不承诺所有邮件客户端像素级一致。发送检查对以下情况给出兼容性提示：

- CSS Grid、Flexbox 等支持不一致的布局。
- 外链字体。
- 固定定位、动画和复杂选择器。
- 超宽内容和缺少移动端适配。

表格布局和内联 CSS 是推荐做法。系统首版不内置跨 Gmail、Outlook、Apple Mail 的远程截图服务。

## 10. 测试策略

### 10.1 单元测试

- 完整文档结构和允许标签被保留。
- 脚本、表单、iframe、事件属性和危险 URL 被移除。
- 安全内联 CSS、`style` 和媒体查询被保留。
- 危险 CSS 被移除。
- HTTPS 外链图片被识别并计数。
- 系统资产引用继续解析为 CID。
- HTML 稳定生成可读纯文本。
- 复杂 HTML 切回可视化模式时触发损失提示。

### 10.2 接口与集成测试

- 预览与发送使用相同的清洗结果。
- 单发、回复、模板、群发和重试保持 HTML。
- SMTP 调用同时包含 `text`、`html` 和正确附件。
- 绕过前端提交危险 HTML 仍会被服务端清洗。
- 失效资产、空正文和未替换变量阻止发送。

### 10.3 组件与端到端测试

- 三种模式能够切换并保留内容。
- 导入 HTML 后可预览。
- 外链图片提示可见但不阻止发送。
- 复杂源码切回可视化模式必须确认。
- 模板中的完整 HTML 能加载到写信页面并发送。
- 发送历史展示清洗后的 HTML，不执行主动内容。

## 11. 验收标准

功能完成必须同时满足：

1. 现有富文本邮件行为不退化。
2. 可创建、保存、预览并发送完整 HTML 邮件。
3. 单发、回复、模板和群发均保留 HTML 布局。
4. 预览内容与 SMTP 实际 HTML 使用同一处理结果。
5. 危险 HTML 和 CSS 无法进入预览执行环境或发送内容。
6. 内嵌图片与 HTTPS 外链图片均可用，并显示正确风险提示。
7. 每封邮件都包含可读的纯文本备用版本。
8. 相关单元、集成和端到端测试通过。

## 12. 非目标

本次不包含：

- 自动将任意网页抓取为邮件模板。
- 服务端代理或缓存外链图片。
- 第三方邮件客户端截图与兼容性评分服务。
- 可拖拽搭建复杂营销邮件的区块式页面生成器。
- 未经人工审核的自动发送。
