# 最终退信重发与邮件超链接设计

## 背景

系统当前在 SMTP 服务器接受邮件后立即把邮件标记为 `SENT`，并由这条记录启动 24 小时联系保护。如果收件服务商稍后返回最终退信，系统仍把该邮件视为成功，运营无法在系统内重试，也无法快速获取某次群发的退信地址。

可视化邮件编辑器同时缺少插入、修改和移除超链接的操作。

## 目标

- 自动识别标准投递状态通知（DSN）中的最终失败 `Action: failed`。
- 只有已与原始发件安全匹配的最终失败才解除该次发信造成的 24 小时保护。
- `Action: delayed` 不解除保护，避免原邮件稍后投递成功时发生重复发送。
- 为群发批次生成可复制的待重发退信名单，地址之间使用英文分号 `;` 且不加空格。
- 运营可直接在系统内对退信收件人发起新的重发批次。
- 可视化编辑器支持安全的超链接插入、修改和移除。

## 非目标

- 不实现主管理员强制跳过 24 小时保护，也不增加审批流。
- 不把 SMTP 已接受等同于收件端已读或已确认投递。系统仍以“SMTP 已接受且未收到可匹配的最终失败 DSN”作为成功状态。
- 不对延迟投递自动重发。
- 不把未匹配退信人工猜测到某个用户或发信记录。
- 不改变现有退订、暂停联系、收件人去重和域名级 2–4 分钟群发间隔规则。
- 不自动无限重发；每轮重发必须由运营人员主动确认。

## 方案选择

采用“结构化投递事件 + 发信状态回写 + 批次血缘重发”。

不仅在收件箱页面展示退信文本，因为 24 小时保护、群发统计和重发入口都需要可查询的结构化状态。也不直接删除原发信记录：原邮件、会话、群发记录和退信证据都必须保留。

## 数据模型

### 邮件状态

`MailMessageStatus` 增加 `BOUNCED`。已被 SMTP 接受的发件先保持 `SENT`；后续收到且匹配到 `Action: failed` 时才转为 `BOUNCED`。

`MailMessage` 增加：

- `bouncedAt`：首次确认最终退信的时间。
- `bounceStatusCode`：DSN `Status` 值，例如 `5.1.1`。
- `bounceDiagnostic`：经长度限制的 `Diagnostic-Code`，供运营排查。

原始主题、正文、收发件人、会话、附件、发送时间和 provider message ID 不做删除或覆盖。

### 投递事件

新增 `MailDeliveryEvent`，用于保留 DSN 证据并保证同步幂等：

- `id`、`mailboxId`、`outboundMessageId`。
- `inboundProviderMessageId`：退信通知自身的 Message-ID。
- `action`：规范化为 `FAILED`、`DELAYED`、`DELIVERED`或 `OTHER`。
- `recipientNormalized`：该 DSN 块对应的规范化收件地址。
- `statusCode`、`diagnosticCode`、`reportedAt`、`createdAt`。

唯一约束为 `inboundProviderMessageId + recipientNormalized + action`。同一封 DSN 重复同步不会重复改状态或重复计数；一封包含多个收件人块的 DSN 可以产生多条事件。

### 群发收件人与重发血缘

`MailBatchRecipientStatus` 增加 `BOUNCED`。当关联发信转为 `BOUNCED` 时，对应收件人从 `SENT` 转为 `BOUNCED`，并写入退信时间和摘要。

`MailBatch` 增加可空的 `retryRootBatchId`：普通批次为空；重发批次指向最初的原始批次。

`MailBatchRecipient` 增加可空且唯一的 `retryOfRecipientId`，指向上一轮被重发的收件人记录。每条退信记录最多只能生成一条直接重发记录，从数据层防止双击或并发请求创建重复任务。

批次详情以每个原始收件人的最新血缘叶子状态计算“待重发退信”。因此：

- 初次退信后出现在名单中。
- 已创建重发任务的地址不再作为待重发项重复创建。
- 重发后如果再次最终退信，新的叶子记录再次出现在同一原始批次的待重发名单中。

## DSN 识别与匹配

### 识别规则

收信同步优先检查 MIME `message/delivery-status` 部分，并解析每个收件人块的 `Action`、`Final-Recipient`/`Original-Recipient`、`Status` 和 `Diagnostic-Code`。对于不完整但在正文中明确包含标准字段的 DSN，可使用受限的行级解析作为兼容路径。

只有解析后的 `Action` 精确等于 `failed`（忽略大小写和字段周围空白）才会触发最终退信状态变更。不通过主题中的“退信”、“Mail delivery failed”或普通正文自由文本判定最终失败。

### 原发信匹配顺序

1. DSN 中的 `Original-Message-ID` 或附带原邮件的 `Message-ID`，与发信 `providerMessageId` 精确匹配，比较时规范化尖括号和空白。
2. DSN 自身的 `In-Reply-To`/`References` 与发信 `providerMessageId` 匹配。
3. 仅当前两者缺失时，才在同一发件箱、最近 30 天、同一规范化收件地址中查找候选。只有候选唯一，且规范化主题也一致时才允许关联。

任一步出现多个候选都视为未匹配，不解除 24 小时保护。未匹配 DSN 仍以 `MailMessageStatus.UNMATCHED` 保存在收信记录中，并标记未匹配原因，便于排查。

### 状态处理

- `FAILED`：在一个数据库事务内写入投递事件，把原发信从 `SENT` 转为 `BOUNCED`，并同步回写群发收件人和批次统计。
- `DELAYED`：写入投递事件，原发信和群发收件人继续保持 `SENT`，24 小时保护不变。
- `DELIVERED` 或其他可解析动作：仅保留事件，不改变发信状态。
- 如果同一原发信已经是 `BOUNCED`，重复的最终退信只保留新事件，不再次调整统计。

可识别且已匹配的 DSN 作为投递事件存储，不作为用户回复进入邮件会话，也不创建“用户已回复”通知。

## 24 小时保护语义

发送前检查改为查看该用户最近一次实际发信尝试：

- 最近一次为 `SENT`，且 `sentAt` 距当前不足 24 小时：继续拦截。
- 最近一次为 `BOUNCED`：允许重发，不再回看更早的 `SENT` 来拦截这次退信重试。
- 重发被 SMTP 接受后，新发信成为最近一次 `SENT`，立即重新启动 24 小时保护。如果它后续又被最终退信，同步完成后再次解除。
- 退信尚未被收信同步取回时，系统仍按 `SENT` 拦截。这是避免在投递结果未知时重复发送的安全默认。

该规则同时适用于单封发送、邮件回复和群发。不增加任何角色的强制跳过入口。

## 群发失败名单与系统内重发

### 批次详情

原始群发批次详情增加“最终退信”区块，显示：

- 待重发人数。
- 英文分号连接的规范化邮箱名单，例如 `a@example.com;b@example.com;c@example.com`。
- “复制邮箱名单”按钮。没有待重发地址时禁用。
- “重新发送退信用户”按钮。点击后二次确认，对话框明确显示人数、发件箱、主题以及“将继续使用每封 2–4 分钟随机间隔”。

名单只包含血缘中最新一轮明确为 `BOUNCED` 且尚未创建下一轮重发的地址。以下项目不进入该名单：`DELAYED`、SMTP 调用当场失败、退订、暂停联系、24 小时跳过、内部处理错误和未匹配 DSN。

### 创建重发批次

二次确认后，服务端在一个事务中重新计算待重发叶子记录并创建新批次：

1. 新批次继承原始批次的发件箱、主题、文本正文、HTML 正文和附件/正文图片关联；不允许在这个快速重发流程中改内容。
2. 新批次只包含事务开始时仍是待重发的叶子收件人，并使用该叶子记录中已发生退信的 `emailNormalized` 快照，不在快速重发时静默替换为用户资料中的其他地址。
3. 每个新收件人通过 `retryOfRecipientId` 关联上一轮记录，新批次通过 `retryRootBatchId` 关联最初批次。
4. 发送时重新执行退订、暂停联系和当前邮箱可用性检查；不因这是重发而绕过其他安全规则。
5. 24 小时检查按“最近一次发信是 `BOUNCED`”的新语义放行。
6. 重发批次使用现有域名级 2–4 分钟随机发送间隔，不允许并发或绕过节流。

如果用户在二次确认前后状态变化，服务端以事务中重新计算的结果为准。零个可重发地址时不创建空批次，并返回可读提示。

## 单封邮件退信

单封发信或回复被标记为 `BOUNCED` 后：

- 邮件详情显示“最终退信”、退信时间、状态码和经过安全输出的诊断摘要。
- 任务页提供“重新编辑并发送”，进入现有写信器，预填上一封的主题和正文，但仍需运营人员主动确认发送。
- 只当关联任务仍为 `WAITING_USER`，且该退信邮件仍是任务最新一封实际发出的邮件时，才把任务恢复为 `IN_PROGRESS`。已完成、已取消、已暂停、已发出更新邮件或已因其他活动改变的任务不被旧退信回写覆盖。
- 写入任务活动，记录邮件 ID、退信时间和状态码。

## 可视化编辑器超链接

可视化编辑器工具栏增加“超链接”操作：

- 选中文字后点击可输入链接地址并插入链接。
- 光标位于现有链接内时，弹窗预填当前链接，可修改或移除。
- 没有选中文字时，插入的可见文字使用输入的地址。
- 只允许 `https://` 和 `mailto:`。输入普通域名时自动补全 `https://`；`http://`、`javascript:`、`data:` 和其他协议显示明确错误并不保存。
- 生成的外链统一在新窗口打开，并带有 `rel="noopener noreferrer"`。
- 可视化模式、HTML 源码模式和发送预览保持一致。服务端 HTML 清理仍是最终安全边界，不依赖前端校验。

## API 与权限

- 收信同步 API 和 Worker 共用同一个 DSN 解析、匹配和状态应用服务，避免手动同步与定时同步结果不一致。
- 批次详情 API 返回血缘汇总后的待重发人数和地址数组；分号字符串由界面按数组顺序生成。地址按规范化邮箱升序排列，保证页面和复制结果稳定。
- 新增批次退信重发 API，服务端执行权限检查、事务内重算和幂等创建。权限沿用现有创建群发的角色范围，不为重发扩大权限。
- 重发请求必须带客户端幂等键。同一键重放返回同一批次；不同键的并发请求仍受 `retryOfRecipientId` 唯一约束保护。

## 统计、审计与观测

- `SENT -> BOUNCED` 时，批次 `sentRecipients` 减一，`failedRecipients` 加一；只在首次状态转换时调整。`totalRecipients` 不变。
- 已完成批次后续发生退信时，批次结果改为 `PARTIAL_FAILURE`；如果所有原已发送收件人都最终退信，改为 `FAILED`。
- 重发批次独立统计，原始批次同时提供血缘汇总的“待重发退信”数字，不改写原始的历史总人数。
- 写入审计日志：`MAIL_FINAL_BOUNCE_MATCHED`、`MAIL_BOUNCE_UNMATCHED`、`MAIL_BOUNCE_RETRY_BATCH_CREATED`。记录实体 ID、批次 ID、收件地址、状态码和操作人；不记录邮箱密码或完整原始邮件。
- 同步结果增加 `deliveryEvents`、`finalBounces`、`delayedDeliveries`、`unmatchedBounces` 计数，便于管理员确认识别是否工作。

## 错误处理

- DSN 解析失败：作为未匹配收信保存，不更改发信状态。
- DSN 匹配不唯一：作为未匹配收信保存，不更改发信状态。
- 退信事务中任一写入失败：整个该 DSN 块回滚，下次同步重试，不留下“有事件但状态未变”的半成品。
- 重发批次创建冲突：返回已创建的批次或“没有待重发地址”，不创建重复收件人。
- 原发件箱配置已删除或禁用：保留待重发名单，不创建无法执行的批次，提示先恢复或选择可用发件箱。快速重发默认不允许换发件箱，避免血缘语义和投递诊断被混淆。

## 测试范围

### DSN 解析和匹配

- 标准 `message/delivery-status` 中的 `failed`、`delayed`、`delivered` 和多收件人块解析。
- 正文兼容路径只接受明确 `Action:` 字段，不根据主题或自由文本误判。
- Message-ID 两级匹配、安全唯一回退、多候选拒绝匹配和未匹配保存。
- 同一 DSN 重复同步及并发手动/Worker 同步的幂等性。

### 状态和 24 小时保护

- `failed` 把 `SENT` 转为 `BOUNCED`并解除保护。
- `delayed` 保持 `SENT` 并继续拦截。
- 未匹配和解析失败不解除保护。
- 最近一次是 `BOUNCED` 时不回看更早 `SENT`；重发被 SMTP 接受后立即重启保护。
- 批次统计只在首次 `SENT -> BOUNCED` 时调整。
- 关联任务仅在安全状态前提下从 `WAITING_USER` 恢复为 `IN_PROGRESS`。

### 失败名单和重发

- 名单仅包含最新血缘叶子为 `BOUNCED` 的收件人，以 `;` 无空格连接并稳定排序。
- 当场 SMTP 失败、`delayed`、退订、暂停联系、跳过和内部错误不进入名单。
- 重发批次继承内容与资产，只生成待重发收件人，并继续经过 2–4 分钟域名节流。
- 双击、请求重放和并发重发不会为同一叶子收件人生成多个下一轮。
- 再次退信后，新叶子重新出现在原始批次的待重发名单中。

### 超链接

- 有选区插入、无选区插入、修改现有链接和移除链接。
- 普通域名补全 `https://`，`https://` 和 `mailto:` 保留。
- 不安全协议被前端拒绝，即使绕过前端也会被服务端清理。
- 可视化编辑、HTML 源码和预览往返不丢失安全链接。

### 回归验证

- 现有单封发送、回复、群发、收信同步、邮件会话、附件、图片、源码编辑、HTML 清理和域名节流测试继续通过。
- 数据库迁移、Prisma 生成、单元/集成测试、类型检查、代码检查和生产构建全部通过。

## 验收标准

- 一封已发送邮件只有在系统同步到、解析出并安全匹配 `Action: failed` 后才被视为最终失败。
- `Action: delayed` 在任何时候都不会导致重发放行。
- 最终退信可再次发送；新邮件被 SMTP 接受后重新启动 24 小时保护。
- 群发页面自动给出稳定、可复制的英文分号失败邮箱名单，并可经二次确认在系统内创建重发批次。
- 重发邮件保持原发件箱和内容，且仍使用域名级 2–4 分钟随机间隔。
- 单封退信不会破坏原邮件会话，并提供明确的重新编辑入口。
- 可视化编辑器可插入、修改、移除安全超链接，实际发送内容与预览一致。
