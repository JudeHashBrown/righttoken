# 运营导航、筛选与已发送邮件设计

## 目标

降低运营人员从“发现问题”到“处理明细”的操作成本，并让用户筛选和邮件记录更容易理解：

1. 看板前三个任务指标可以点击，落地页结果数量与指标口径一致。
2. 用户中心可以一次筛出所有地区未识别用户。
3. A–G 分组筛选始终展示各组的简短定义。
4. 邮件中心可以查看所有已成功发送的邮件。

## 方案选择

采用“可复用查询参数 + 现有工作台视图”的方案，不新增独立页面。

- 看板指标通过稳定 URL 参数进入任务中心，由任务查询层实现相同口径。
- 地区筛选增加独立的 `locationState=unrecognized` 语义，避免把“未识别”伪装成普通地区文本。
- 分组说明直接包含在筛选按钮中，不使用悬浮提示，保证运营无需额外操作即可看到。
- 已发送邮件作为邮件中心的 `sent` 视图，复用现有列表和详情工作台。

不采用只在前端过滤当前页的方案，因为它无法保证数量与数据库总量一致；不采用新建四个独立页面的方案，因为会复制现有任务、用户和邮件工作台。

## 看板指标跳转

前三个指标卡成为完整可点击区域，并支持键盘聚焦：

- 今日待处理：`/tasks?view=all&due=today`
- 紧急任务：`/tasks?view=all&priority=URGENT&scope=open`
- 用户待回复：`/tasks?view=all&origin=EMAIL_REPLY&scope=open`

任务查询增加：

- `due=today`：使用上海时区当天起止时间，限定开放任务状态。
- `origin=EMAIL_REPLY`：限定开放任务状态和邮件回复来源。

点击后，任务中心保留对应筛选状态，并在页面标题或筛选控件中明确展示当前口径。

## 未识别地区筛选

用户中心地区控件改为选择列表：

- 全部地区。
- 未识别。
- 当前数据库中已存在的非空地区，去重并排序。

选择“未识别”时传递 `locationState=unrecognized`，查询条件为：

```text
countryCode IS NULL AND region IS NULL
```

国家已确认但省 / 州 / 地区为空的用户不属于“未识别”。

## 分组两行说明

分组筛选维持业务优先顺序：

- 全部：全部用户
- F：服务异常
- A：注册未支付
- B：支付未完成
- C：充值未调用
- D：长期未调用
- E：余额不足
- G：健康或其他

每个按钮使用上方组别、下方定义的两行布局。桌面端保持同一行展示全部按钮；窄屏允许水平滚动，不隐藏说明。

## 已发送邮件

邮件工作区增加 `sent` 视图和统计卡：

- 只查询 `direction=OUTBOUND` 且 `status=SENT` 的邮件。
- 按 `sentAt DESC` 排序，`sentAt` 为空时使用 `createdAt` 兜底。
- 每封邮件独立显示，不能按会话合并。
- 列表展示主题、收件人、正文摘要和发送时间。
- 点击后展示发件人、收件人、主题、发送时间、正文和附件。
- 普通运营人员继续受现有用户 / 任务范围限制，管理员可查看全部。

## 测试

- 组件测试验证三个指标链接的精确 URL。
- 任务查询集成测试验证 `due=today`、`priority=URGENT` 和 `origin=EMAIL_REPLY` 的口径。
- 用户查询集成测试验证“未识别”仅返回国家和地区均为空的用户。
- 分组组件测试验证每组定义始终可见。
- 邮件筛选单元测试验证 `sent` 是合法视图。
- 邮件查询集成测试验证已发送计数、排序、权限和单封详情。
