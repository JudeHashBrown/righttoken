# RightToken 企微通知闭环设计

## 1. 目标

在现有后台通知、企微群机器人和邮件通知能力上，增加企业微信自建应用直发能力，让每个需要运营介入的任务优先通知当前负责人，并在紧急、无人负责或持续失败时自动升级到运营群和主管理员。

首版必须完成：

- 企业微信自建应用凭据配置与连接测试。
- 后台成员与企业微信成员 `UserID` 的一对一映射。
- 按任务负责人发送企业微信应用消息。
- F 组、服务异常和严重超时的群机器人升级通知。
- 无负责人时通知主管理员并发送运营群。
- 企微鉴权缓存、发送重试、错误分类和邮件兜底。
- 消息中不出现完整邮箱、注册 IP 或其他敏感信息。
- 消息链接可直接打开对应用户或任务页面。

## 2. 方案

采用“企业微信自建应用直发 + 运营群机器人兜底”的混合方案。

- 自建应用负责精准通知运营负责人。
- 群机器人负责紧急事件、无人负责事件和发送失败升级。
- 后台通知始终保留，不因外部渠道不可用而丢失任务。
- 邮件只用于策略要求的多渠道通知和企微最终失败后的主管理员兜底。

不采用以下方案：

- 仅群机器人：无法精准通知负责人。
- 仅自建应用：缺少运营群的公共异常视图和兜底通道。

## 3. 配置与权限

### 3.1 企业微信自建应用

主管理员在系统设置中配置：

- 企业 `CorpID`
- 应用 `AgentID`
- 应用 `Secret`
- 启用状态
- 连接名称

凭据使用现有字段加密机制保存，不写入仓库、镜像、日志或浏览器回显。保存后前端仅显示已配置状态和非敏感摘要。

连接测试流程：

1. 使用 `CorpID` 和 `Secret` 获取企业微信访问令牌。
2. 向指定的内部测试成员发送不包含用户信息的测试消息。
3. 保存最后测试时间、最后成功时间和脱敏错误代码。

### 3.2 群机器人

保留现有群机器人 Webhook 配置。Webhook 继续加密存储，不在前端回显完整地址。

### 3.3 成员映射

后台成员增加可选的 `wecomUserId`：

- 主管理员和管理员可编辑成员映射。
- 一个启用成员最多对应一个企业微信 `UserID`。
- 同一个企业微信 `UserID` 不能分配给多个后台成员。
- 成员停用后不再接收新的直发通知。
- 没有映射的负责人视为直发渠道不可用，进入升级流程。

## 4. 通知路由

### 4.1 普通和重要任务

- 后台通知：始终创建。
- 企微自建应用：发送给当前任务负责人。
- 群机器人：默认不发送。
- 邮件：由现有通知策略决定。

### 4.2 紧急任务

以下事件属于紧急通知：

- 用户进入 F 组。
- 服务异常仍处于活动状态。
- 任务达到严重超时阈值。
- 企微通知连续失败并超过最大重试次数。

处理方式：

- 直发当前负责人。
- 同时发送运营群。
- 没有负责人时直发主管理员并发送运营群。
- 邮件通知主管理员。

### 4.3 邮件事件

- 用户回复：通知当前负责人。
- 退信：通知当前负责人并在后台标记邮件不可达状态。
- 退订：通知当前负责人，同时保留现有退订拦截，禁止后续营销邮件发送。

### 4.4 负责人和分组变化

- 负责人变化后，尚未处理的通知只发送给新负责人。
- 用户分组变化后，新产生的任务按最新分组和最新负责人通知。
- 已经发送成功的历史通知不撤回。

## 5. 消息结构与隐私

企业微信消息仅包含：

- 用户脱敏编号
- 国家和省级地区
- A–G 分组
- 触发原因
- 优先级
- 剩余处理时间或超时状态
- “查看任务”或“查看用户”链接

消息不得包含：

- 完整邮箱
- 注册 IP
- 邮箱密码、企微密钥、内部 API 密钥
- 支付凭据或其他直接身份信息

运营在登录 RightToken 主站管理后台后，才可在授权页面查看完整邮箱和 IP。开发环境继续使用免登录身份，但消息链接结构必须与未来主站单点登录兼容。

## 6. 组件边界

### 6.1 凭据与成员映射

- 企微应用配置负责校验、加密保存和健康状态。
- 成员映射只保存企业微信 `UserID`，不保存成员手机号。

### 6.2 企业微信客户端

客户端负责：

- 获取和缓存访问令牌。
- 在令牌即将过期前刷新。
- 发送应用文本卡片消息。
- 规范化企业微信错误响应。

客户端不负责：

- 选择通知接收人。
- 判断是否需要群发。
- 写入任务或用户状态。

### 6.3 通知路由服务

路由服务根据任务优先级、事件类型、负责人映射和通知策略生成通知意图：

- `IN_APP`
- `WECOM_APP`
- `WECOM_ROBOT`
- `EMAIL`

相同任务、事件和渠道使用稳定幂等键，避免工作进程重试产生重复消息。

### 6.4 通知投递工作进程

工作进程读取待发送或可重试通知：

1. 加载当前有效配置。
2. 确认任务的最新负责人。
3. 使用对应适配器发送。
4. 保存供应商消息 ID、尝试次数和结果。
5. 根据错误类别决定重试、配置告警或最终失败升级。

## 7. 错误处理

### 7.1 可重试错误

- 网络超时
- HTTP 429
- 企业微信服务端错误
- 临时令牌失效

处理方式：

- 令牌失效先刷新令牌并重试一次。
- 其他错误使用现有队列的指数退避策略。
- 达到最大次数后标记 `FAILED` 并触发主管理员兜底。

### 7.2 不可重试错误

- `CorpID`、`AgentID` 或 `Secret` 无效
- 接收成员不存在
- 应用无权联系该成员
- 请求内容违反企业微信限制

处理方式：

- 保存脱敏错误代码。
- 在设置页显示配置异常。
- 对单个成员映射错误，升级到主管理员和运营群。
- 对全局鉴权错误，暂停应用直发，保留后台任务和群机器人/邮件兜底。

## 8. 数据模型

### 8.1 成员

`Member` 增加：

- `wecomUserId String? @unique`

### 8.2 集成凭据

继续使用 `IntegrationCredential`，新增种类：

- `WECOM_APP`

加密配置包含：

- `corpId`
- `agentId`
- `secret`

现有 `WECOM_ROBOT` 保持不变。

### 8.3 通知渠道

通知渠道枚举增加：

- `WECOM_APP`

现有企微机器人通知统一使用：

- `WECOM_ROBOT`

如果数据库当前渠道名为通用 `WECOM`，迁移时将历史数据解释为群机器人，不丢失历史记录。

## 9. 管理界面

### 9.1 系统设置

企微区域拆分为两个紧凑模块：

- 企业微信应用：连接名称、CorpID、AgentID、Secret、启用状态、保存、测试。
- 运营群机器人：连接名称、Webhook、启用状态、保存、测试。

页面不展示架构说明、鉴权流程、重试算法或其他后台设计语言。

### 9.2 成员管理

成员编辑区域增加“企微 UserID”字段和映射状态：

- 已映射
- 未映射
- 成员已停用

只显示运营需要理解的状态，不显示内部渠道枚举和错误堆栈。

## 10. 测试与验收

自动化测试使用本地模拟企业微信服务器，不向真实企业微信发送消息。

必须验证：

1. 凭据加密保存且接口不回显 Secret。
2. 访问令牌缓存和过期刷新。
3. 普通任务只直发负责人。
4. F 组任务同时直发负责人和群机器人。
5. 无负责人或无企微映射时通知主管理员和运营群。
6. 邮件回复、退信和退订触发正确通知。
7. 完整邮箱、注册 IP 和密钥不出现在消息体。
8. 任务链接指向当前环境的任务详情页。
9. 429、超时和服务端错误进入重试。
10. 无效凭据不重试并显示配置异常。
11. 超过最大重试次数后产生后台和邮件兜底通知。
12. 重复任务或队列重放不产生重复企微消息。

本地真实连接测试只允许向公司内部测试成员和测试群发送不含用户信息的连接消息。

## 11. 发布边界

首版不包含：

- 从企业微信通讯录自动同步成员。
- 企业微信内审批、表单或双向聊天。
- 通过手机号或邮箱猜测企微成员。
- 撤回已经发送的企业微信消息。
- 在企业微信消息中展示完整用户隐私数据。

完成本地验证后，先部署测试环境，再由主管理员配置真实企业微信凭据。凭据和真实用户数据不得提交到 GitHub。
